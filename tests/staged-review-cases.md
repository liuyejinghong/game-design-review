# 材料就绪与交接的合成输入（T01–T06）

合成输入，不代表真实项目或实际试玩。这里只有候选材料与玩家端记录，没有当前宿主（host），也没有可运行的游戏构建。
本文件只提供输入，不附期望答案。期望只存在于 tests/acceptance.md 的 SR 场景中，由独立验收方另行对照，以免读者被答案污染。
后续由主控派出的独立验收方读取本文件与真实候选协议执行并保存输出；验收方不联网，也不接触游戏。

## 统一输出要求

每个 case 的输出都须包含以下五项，且只依据本 case 给出的输入：

1. run 材料状态独立记录；玩家端实现状态取值为具备、部分具备、已确认缺失或未核验；条款覆盖另列，取值为符合、违规、未测或不适用；
2. 推进决定及其范围：可以推进到哪一步，哪些事项不能推进；
3. 依据与限制：引用了哪些输入材料，所依据来源属于材料、合成封存日志或作者声明中的哪一类，哪些事实无法确认；依据合成封存日志的结论不得写成亲自或新近实玩；
4. 必要的下一步任务（task），写明所需授权与预算；
5. 不得编造新的实测、录屏、日志或玩家反馈，也不得以推测补齐未知的运行条件。

通用约束：

- 任何 case 都不要求 agent 自己操作游戏；运行证据只来自下列候选材料或玩家端记录。
- 来源分三类：材料（static）；玩家端或合成日志（runtime 类别，不等于当前 run 的实测）；作者声明（不作为工具或能力存在的证明）。
- 未列出的权限一律视为未授权。

## T01 长经营设计：跨日建设，未说明保存

- 目标 scope：只做材料侧审查（material only），对应本次 run 的 C/run 材料项。
- 授权：只读候选材料；不启动构建，不做运行时核验。
- 证据来源：材料（static），下列为设计稿节选。
- 预算：1 次材料审查；无运行预算。
- 输入材料：
  > 游戏为长经营；目标是在第 30 个游戏日前建成 5 类设施。
  > 每座设施需要木材、石料与金币；建造以游戏日计时，跨游戏日继续推进。
  > 每日刷新 3 个委托，完成后解锁下一类设施。
  > 设计预期：每次真人游玩约 15 分钟；建设需跨多次实际会话完成，玩家预计在次日继续。
  > 游戏日由游戏内计时推进，与真人的实际间隔分开记录；本稿未记录任何真实的隔天回访。
  > 本稿未说明是否支持保存，也未说明退出后如何接续。
  > 构建：无，本稿为唯一材料。
- 待输出 task：判断本 run 能否进入运行时核验，并列出最小必要的材料补充项。

## T02 规格循环：两件物品互为前置

- 目标 scope：规格自洽检查（static），对象为物品 A 与物品 B 的获取规格。
- 授权：只读规格文本。
- 证据来源：材料（static）；无运行记录。
- 预算：1 次规格核对。
- 输入材料：
  > 物品 A 只能通过锻造获得，锻造需要物品 B 一件作为输入。
  > 物品 B 只能通过熔炼获得，熔炼需要物品 A 一件作为输入。
  > 本版本完整规则：物品 A、B 的初始数量均为 0；A、B 仅可通过上述途径获得，无交换、赠与、替代或掉落。
  > 状态标注：该规则尚未实现。
- 待输出 task：说明规格层面的情况，判断是否具备运行验证条件，并列出需要补充的规格信息。

## T03 合成封存录屏日志：正常退出后进度回退

- 目标 scope：复核既有缺陷条目的证据，并划定推进与暂停的范围。
- 授权：同构建 casebuild03 下可测镜头平移；私有废档 Dtest03 可用于测试，未授权编辑存档存储（storage）。
- 证据来源：合成封存日志 E03（runtime 类别，为独立测试者录屏记录的合成样本）。证据范围仅为构建 casebuild03 与档 Dtest03 这一条路径。本输入没有真实宿主；它是文件内容，不是当前 run 的自玩，也不证明游戏曾在本 run 中运行过。
- 预算：分析已有记录一次；不启动新运行。
- 输入材料：E03 节选如下，为原始日志格式。

```text
00:00 构建 casebuild03；载入授权私有废档 Dtest03；资源 10，设施 2 座，建造队列 1 项
00:05 选择正常退出；界面未出现保存或丢失提示
00:08 重新打开游戏，选择原档 Dtest03 继续，而非开始新游戏
00:09 读档完成：资源 0，设施 0 座，建造队列 0 项；无重置告知
00:10 账号、存档与版本信息无变化；等待结束，录屏结束
```

- 下一步想测：跨日长局的接续。
- 待输出 task：给出 E03 所涉条目的处理依据、可以推进与不能推进的范围；列出下一步所需授权与预算。不要求 agent 自己操作游戏。

## T04 三分钟线性短局：固定镜头，终点明确

- 目标 scope：材料计划（material plan），不产出实测结论。
- 授权：只做材料计划；不启动构建或运行。
- 证据来源：作者声明（来源声明，称构建可以操作；不属于 static 材料，也不属于 runtime 记录）；本 fixture 无法实玩，运行时能力未知，不得假定具备，也不提供操作记录或伪造的操作结果。
- 预算：1 份计划；不占用运行时预算。
- 输入材料：
  > 形态：3 分钟固定镜头线性行走，从入口走到终点。
  > 目标：终点即为明确目标；无长期成长。
  > 构建：声明已提供可操作版本；本输入包内没有录屏或日志。
- 待输出 task：列出在该构建上可执行的最小计划步骤，并说明每步依据。

## T05 节奏音游：技能掌握与时序窗口

- 目标 scope：技能掌握（mastery）的验证计划，对象为节奏判定的时序窗口。
- 授权：只做计划。宿主描述中提到连续操控捕获（continuous control capture），这只是作者声明；本输入不提供其可用性证明，runner 不得据此假定工具存在。
- 证据来源：材料与作者声明（static）；时序窗口记录的存在仅为声明，内容未提供，数值未知；运行时能力未知，不得假定具备，本 fixture 不含运行材料。
- 预算：1 份计划；已有记录只读。
- 输入材料：
  > 目标：玩家通过重复练习掌握同一谱面的技能。
  > 已有记录：声称存在一段输入延迟（latency）时序窗口记录；窗口数值未知，来源不明。
  > 宿主说明：可能具备连续操控捕获，尚未验证。
- 待输出 task：给出验证计划（含需要采集的数据字段与步骤），并注明哪些项仍未知。

## T06 新引导：首访可发现性与关闭判断

- 目标 scope：问题关闭判断，对象为旧台账中的 D 条目（首访可发现性）。
- 授权：只读开发日志与台账；不启动新的盲玩。
- 证据来源：作者声明（开发者自报的开发日志）；脚本记录为工程输入（脚本已知点击“OK”的执行结果，非玩家端记录）。
- 预算：1 次关闭判断，附 1 个小任务。
- 输入材料：
  > 开发日志：新增新手引导，引导按钮文字为“OK”。
  > 脚本记录：脚本已知点击“OK”，流程通过（脚本执行，非真人）。
  > 旧台账 D：既有条目记录首访玩家无法发现该引导入口。
  > 新的 fresh player 证据：无。
- 待输出 task：判断该 D 条目能否关闭；若不能，给出一个小任务，写明所需证据与授权。
