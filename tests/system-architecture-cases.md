# 系统架构与内容生产管线的合成输入（S01–S06）

合成输入，不代表真实项目、真实仓库、真实宿主（host）或实际试玩。本文件中的工程摘要、代码摘录、黑盒日志、制作记录与校验报告都是 fixture 内的合成材料，只代表本 fixture 的相应证据类别（静态摘要、合成黑盒日志、作者声明，或权限与请求本身），不对应任何真实路径或真实运行结果。六个 case 均没有真实宿主。
本文件只提供输入，不附期望答案。期望只存在于 tests/acceptance.md 的 A49–A61 场景中，由独立验收方另行对照，以免读者被答案污染。各 case 标题只描述场景，不包含结论。
后续由主控派出的独立验收方读取本文件与真实候选协议执行并保存输出；验收方不联网，不接触游戏，不运行任何构建、脚本或工程执行。

## 统一输出要求

每个 case 的输出都须包含以下四项，且只依据本 case 给出的输入：

1. 加载与轮次时序：说明各输入在本轮中的读取时点，并依据协议说明前置或后置的理由；
2. 证据种类与范围：每条依据属于静态摘要、合成黑盒日志、作者声明，还是权限与请求本身；各自覆盖什么范围，哪些事实无法确认。依据合成黑盒日志的结论不得写成亲自或新近实玩；
3. 矩阵状态与结论：字段按协议的现有实现四态与对照五值填写；若输入未提供参照来源，写明“输入未提供来源”，结论依协议给出；
4. 当前问题、路线与任务分流，以及下一步权限：玩家损害按性质归入 D 或 B，路线归入 R09-A，任务引用 C/D/B/L/G 原 ID；写明下一步所需的授权与预算。

通用约束：

- 任何 case 都不要求 agent 自己操作游戏或运行工程；运行证据只来自下列合成输入。
- 不得编造新的实测、录屏、日志、代码位置或玩家反馈，也不得以推测补齐未知的代码位置或运行条件。缺少必需代码位置时，不得通过假定位构造 E-SA-xxx 证据。
- 来源分类：静态摘要或工程摘录只能定位与支持静态事实；合成黑盒日志属于 runtime 类别，不等于当前 run 的实测；作者声明不作为工具、能力或结果存在的证明。
- 未列出的权限一律视为未授权；“只读”不包含运行、构建、修改、清档、改时钟或注入存档。
- 每个 case 的权限与预算都是上限，不是目标。
