# 调用与裁决验收场景

这些是合成任务/证据，用于协议走查，不是真人样本、游戏发现或已经完成的浏览器端到端测试。每次改动编排/裁决需逐条比对；真实宿主验收须另外提供录制和实际 run。

| 编号 | 输入或情境 | 必须得到的行为 | 禁止的结果 |
|---|---|---|---|
| A01 | “完整多角度评审，并给分”＋合法入口/废档 | 定靶、适用 R01–R05、R06、R07、R08；首访先封存 | 盲玩者收到候选分数或内部正确路线 |
| A02 | “这轮只改背包操作，不需要打分” | 迭代相关交互/核心快检、R07；有旧发现做回归 | 强制重跑全部、默认输出评分 |
| A03 | “只给新版评分”，已有同版充分原始证据 | 回读核验、引用诊断、补真实缺口再 R08 | 只读旧分数或摘要重新包装 |
| A04 | 没有独立子代理，宿主注入了旧对话 | 标受限黑盒探索和污染，继续可做项 | 声称真实新手隔离或独立多人样本 |
| A05 | 两个专项同时使用同一服务端存档 | 串行和状态交接，或授权独立废档 | 并行消费后仍声称可比对照 |
| A06 | 三个视角引用同一条原始录制 | 同 ID 引用；同一行为问题合并一次 | 三次独立复现、三票支持或重复扣分 |
| A07 | 新手找不到入口，熟练者三秒完成 | 保留两种适用条件，检查发现成本 | 以“习惯了”撤销新手问题 |
| A08 | 候选 P0 只有一段早期数值样本 | 最强反例与第二局面补测，预算不足留待确认 | 平均成 P1，或宣布全局最优已证实 |
| A09 | 静态图没显示动画，录制显示反馈 | 按触发/设置/时段核验并更新原判定 | 坚持“没有动效”或换名保住虚假指控 |
| A10 | 同 run 中部署了新版，skill 也升级 | 封存/拆分，记双版本及新尺复评边界 | 把混合证据当同版，把换尺当游戏涨分 |
| A11 | 回访需要隔天，当前只有短间隔或新局 | 原档短回访有范围；隔天效果未测 | 改时钟、新局冒充离线，承诺后台持续玩 |
| A12 | 工具打不开网站；缺真实反馈 | 环境阻塞、计划或静态观察、不评分 | P0 产品故障或默认 1/7/10 分 |
| A13 | 没有真人数据，但要求真人方案 | 给主持/招募/记录方案，标未开展 | 模拟访谈、捏造退出率 |
| A14 | 固定脚本复验通过，但问题是新手可发现性 | 新盲玩补测后再决定是否关闭 | 脚本通过即关闭新手问题 |
| A15 | 9 分候选与确认的核心 P0 冲突 | 回读原始证据，补证/修正论证，保留裁决变更 | 用平均总分抵消 P0 或删掉负面记录 |
| A16 | 确认无战斗、无多人但有表达/探索主打体验 | 相应条款不适用，检查实际体验承诺；能力行仍记传统功能有无与实际替代/合理省略理由 | 因缺传统失败或社交自动判不好玩，或让相应能力行从矩阵消失 |
| A17 | 文字原型完整里程碑，未请求换引擎 | 相关取证后 R09 适配/转段→R06→R07；技术部分未启用 | 重编号 R06–R08 或默认全面引擎调研 |
| A18 | 只问要不要像素化，没有图形切片 | 区分体验、验证缺口与路线，出最小对照计划 | 假称 A/B 已完成，或“像素必然好玩” |
| A19 | 当前正文难读，但计划转图形 | 实测损害按原 T/U 条款提候选，先补最低 UX | 用转段计划撤销当前 P1，或要求原型先做豪华美术 |
| A20 | 主打未来空间物流，只有文字按钮 | 记空间验证缺口、规划可操作切片 | 仅因文字循环跑通宣布空间玩法成立，或把未实现功能直接判 P0 |
| A21 | Canvas 缺 DOM，但视觉交互正常 | 标自动化方式限制；无障碍按承诺另测 | 把定位器失败当游戏缺陷或推断必须换引擎 |
| A22 | 建议换语言，只有网页且不能核验官方文档 | 保留现栈基线、标条件建议/未知、列最小验证 | 承诺代码无损复用、编工时或按引擎名加分 |
| A23 | 精修图形同时改变教程和数值，对比粗糙文字 | 说明混杂因素，只比较方案整体或重做对照 | 将全部变化归因于画风，假称显著提升留存 |
| A24 | R09 重提 R02 的上下文缺陷，同时给出 R09-A 路线 | 缺陷按同一行为证据去重；路线仅入第 8/9 节 | 重复计 P1，或把路线方案加入活跃 P0/P1/P2 |

## 3D / 模拟经营与原生客户端场景（A25–A36）

以下为条件协议走查：按实际提供的客户端、已承诺玩法与真实系统取样判定适用项，不新增轮次、默认采样或评分；静态截图可确认对应可见条款（如文本裁切），不做动态或全局裁决。

| 编号 | 输入或情境 | 必须得到的行为 | 禁止的结果 |
|---|---|---|---|
| A25 | 提供可玩 3D 客户端，要求完整评审但未要求打分 | TD 检查并入既有 R02/R03（必要处 R04/R05）与覆盖表；不新增轮次 | 新建 3D 轮次编号，或默认启用 R08 评分 |
| A26 | 可实际操作的原生 3D 经营客户端（无浏览器） | 按宿主实际具备的操作与取证能力测 TD+MG，由既有 R02/R03/R04 承载 | 因“没有浏览器”拒绝评审，或要求必须存在战斗、离线收益 |
| A27 | 原生客户端只能取离散截图，无法操作或连续捕获 | 相关动态项记未测；对应可见条款按静态证据限定确认，不评分 | 把工具限制判成产品 P0，或断言动态不存在 |
| A28 | 可操作但无存档的短演示（含 2D 经营） | 镜头、输入或可操作的经营动作照常实测；无存档且未承诺/不需要保存 → 该项不适用，已承诺长期接续却无法测 → 未测/缺口 | 因无存档拒绝全部检查，或声称已验证长期接续 |
| A29 | 固定镜头，无跳跃也无战斗的构建 | 按实际功能与主打体验登记适用项；缺失功能不直接判错，但能力行写清传统实现缺失与替代/合理省略理由 | 因缺旋转、跳跃或战斗判错，或把“未提供”写成缺陷后直接从矩阵删行 |
| A30 | 一次转角遮挡导致目标丢失，无真人舒适度数据 | 记录动作、恢复与最强反例；单次失败不自动判 P0 | 宣称测得人体眩晕/舒适度，或据单次样本直接定 P0 |
| A31 | 建造预览可取消，提交后已告知不可逆且无退还 | 先测预览取消与恢复，再在授权档合法提交一次；已有撤销按规则测，已告知不可逆按预告与确认判 | 因缺撤销或退款判错，或跳过取消路径直接提交后索赔 |
| A32 | 服务经营有顾客/订单链，无工厂、物流与离线收益 | 按投入→顾客/订单→履约→收入/目标的实际服务链实测；相应能力行记录替代与合理省略理由 | 按“缺工厂/物流/离线”扣分或拒绝加载经营专项，或因不适用就略去记录 |
| A33 | 两个方案在首个局面收益相同，第二供需局面 A 优势反转 | 保留真实取舍并记录反转；有限样本只证明已测范围 | 用早期同收益判“选择虚假 P0”，或抹掉已见反转 |
| A34 | 库存净流量与容量混排，导致一次错误决策 | 记 MG01 摩擦并回接 U3/I2/N3；核对按钮与面板实际存在 | 因“按钮齐全、无报错”算可用，或直接升 P0 |
| A35 | TD 与 MG 两个视角引用同一条“选中对象误触”原始证据 | 同一 E-ID 复用；R07 合并为一处 D，同根只计一次 | 计成两次复现/两票，或按专项数量重复扣分 |
| A36 | 有重置/再成长系统，无离线收益 | I9 按系统授权测试；I6–I8 依离线承诺启用，两者互相独立 | 要求离线与重置必须同时存在，或因无离线拒绝测试 I9 |

## 同类成熟度与能力对照场景（A37–A48）

以下为合成走查：验证通用能力对照主线的判定口径，不新增轮次、尺子、评分或问题配额；结论与矩阵行须限定实际证据范围。

| 编号 | 输入或情境 | 必须得到的行为 | 禁止的结果 |
|---|---|---|---|
| A37 | 完成度较高的经营构建，未发现设计 P 问题 | 仍交关键能力对照矩阵并写清距成熟同类差在哪 | 因“没问题”省略矩阵，或只写“整体不错” |
| A38 | 长局有显著积累，未宣传存档且试玩中未见保存入口 | 列会话接续能力行查实际实现与损失路径；按已查范围写未核验 | 按“未承诺”标不适用，或因没找到直接判全局缺失 |
| A39 | 存档按钮存在，但读档/恢复边界不明 | 按真实路径与深度记“具备/部分具备/未核验” | 把按钮存在当成熟达标或据此评分 |
| A40 | 已核查 PC 3D 经营参照含多镜头，目标为固定视角 2D | 以共同观察/选中/规划任务为对照记传统功能缺失与替代证据；3D 特定键位/俯仰实现只记录、不直接比，不因平台不匹配强迫判缺 | 强求平移缩放旋转俯仰，或因形态不同判不适用略去该行 |
| A41 | 目标用不同键位映射，完成/取消与恢复路径实测良好 | 按玩家任务与映射可发现性认可替代 | 因键位不一致扣分，或不经任务核查直接判差 |
| A42 | 目标采用不同物流机制，同约束下多局面实证有效 | 结论写“替代成立”，附限制与亮点证据 | 强制对齐参照同款工具，或把替代当差距 |
| A43 | 自称创新，但物流死锁已确证 | 按实证损害与原尺裁决，创新不减免 | 以“创新方向正确”免罪或降级 |
| A44 | 只有官方手册/截图与未核查参照 | 来源标注区分声明与实测，限定静态未核验范围 | 判“达到参照/成熟”，或给出实玩评分 |
| A45 | 参考样本仅 3 个 | 基准 scope 限定“在已查样本中出现” | 宣称“行业普遍/几乎所有同类” |
| A46 | FPS 构建无 ADS、无 reload、无长期存档 | 按子类与玩家任务查替代/合理省略理由 | 按经营模板扣分，或强行要求传统功能清单 |
| A47 | 已核查匹配参照有低成本蓝图/批量增强，目标虽可规划但缺等效批量或分期能力，无实证损害 | 记已核验参照差距或已证实替代及建议，无 D/P；能力行保留有无与替代记录 | 把未提供功能从矩阵消失，因没有蓝图按钮自动判差，或因未提供直接判 P 级 |
| A48 | 局部库存 UI 改动，已有同版基准 | 只查相关模块与依赖、复用已有研究 | 每轮全量重做参照研究或宣称全局成熟度结论 |

## 真正端到端验收的通过条件

用实际可访问游戏和授权废档执行 A01 对应任务，检查至少一个安全操作及状态变化、一份封存的首访日志、各实际启用轮次记录、候选到最终的映射和完整十节报告。
核验没有读答案的首访者、实际调用的角色数量、同存档串行交接、证据文件可打开、动态断言有相应捕获、每个确认问题可复现、未测不计通过。
走查 A25–A48 时，原生客户端场景须在宿主实际提供的客户端上执行操作与取证，新测试档按游戏选用本地或服务端已核查的档位；不新增通用流程。能力对照场景只验证判定口径：矩阵行与结论不得超出已核验证据范围，参照未核验不得判达标。
若无隔离工具或真实等待条件，允许部分完成但必须如实标记；这种结果不叫“完整端到端通过”。媒体分数可因证据不足而暂缺，这不是让执行者编分的理由。

## 静态自动检查

`python scripts/validate.py --self-test` 校验文档契约并对十八种损坏副本做负向自测。它不自动执行上面的玩法情境，也不判游戏好玩。
