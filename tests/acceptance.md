# 调用与裁决验收场景

这些是合成任务/证据，用于协议走查，不是真人样本、游戏发现或已经完成的浏览器端到端测试。每次改动编排/裁决需逐条比对；真实宿主验收须另外提供录制和实际 run。

| 编号 | 输入或情境 | 必须得到的行为 | 禁止的结果 |
|---|---|---|---|
| A01 | “完整多角度评审，并给分”＋合法入口/废档 | 定靶、适用 R01–R05、R06、R07、R08；首访先封存 | 盲玩者收到候选分数或内部正确路线 |
| A02 | “这轮只改背包操作，不需要打分” | 迭代相关交互/核心快检、R07；有旧发现做回归 | 强制重跑全部、默认输出评分 |
| A03 | “只给新版评分”，已有同版充分原始证据 | 回读核验、引用诊断、补真实缺口再 R08 | 只读旧分数或摘要重新包装 |
| A04 | 没有独立子代理，宿主注入了旧对话 | 标受限黑盒探索和污染，继续可做项 | 声称真实新手隔离或独立多人样本 |
| A05 | 两个专项同时使用同一服务端存档 | 串行和状态交接，或授权独立废档 | 并行消费后仍声称可比对照 |
| A06 | 三个视角引用同一条原始录制 | 同 ID 引用；同一行为问题合并一次 | 三次独立复现、三票支持或重复扣分 |
| A07 | 新手找不到入口，熟练者三秒完成 | 保留两种适用条件，检查发现成本 | 以“习惯了”撤销新手问题 |
| A08 | 候选 P0 只有一段早期数值样本 | 最强反例与第二局面补测，预算不足留待确认 | 平均成 P1，或宣布全局最优已证实 |
| A09 | 静态图没显示动画，录制显示反馈 | 按触发/设置/时段核验并更新原判定 | 坚持“没有动效”或换名保住虚假指控 |
| A10 | 同 run 中部署了新版，skill 也升级 | 封存/拆分，记双版本及新尺复评边界 | 把混合证据当同版，把换尺当游戏涨分 |
| A11 | 回访需要隔天，当前只有短间隔或新局 | 原档短回访有范围；隔天效果未测 | 改时钟、新局冒充离线，承诺后台持续玩 |
| A12 | 工具打不开网站；缺真实反馈 | 环境阻塞、计划或静态观察、不评分 | P0 产品故障或默认 1/7/10 分 |
| A13 | 没有真人数据，但要求真人方案 | 给主持/招募/记录方案，标未开展 | 模拟访谈、捏造退出率 |
| A14 | 固定脚本复验通过，但问题是新手可发现性 | 新盲玩补测后再决定是否关闭 | 脚本通过即关闭新手问题 |
| A15 | 9 分候选与确认的核心 P0 冲突 | 回读原始证据，补证/修正论证，保留裁决变更 | 用平均总分抵消 P0 或删掉负面记录 |
| A16 | 确认无战斗、无多人但有表达/探索主打体验 | 相应条款不适用，检查实际体验承诺 | 因缺传统失败或社交自动判不好玩 |

## 真正端到端验收的通过条件

用实际可访问游戏和授权废档执行 A01 对应任务，检查至少一个安全操作及状态变化、一份封存的首访日志、各实际启用轮次记录、候选到最终的映射和完整十节报告。
核验没有读答案的首访者、实际调用的角色数量、同存档串行交接、证据文件可打开、动态断言有相应捕获、每个确认问题可复现、未测不计通过。
若无隔离工具或真实等待条件，允许部分完成但必须如实标记；这种结果不叫“完整端到端通过”。媒体分数可因证据不足而暂缺，这不是让执行者编分的理由。

## 静态自动检查

`python scripts/validate.py --self-test` 校验文档契约并对五种损坏副本做负向自测。它不自动执行上面的玩法情境，也不判游戏好玩。
