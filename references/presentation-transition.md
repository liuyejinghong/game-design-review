# 表现适配与转段路线评审（R09）

本视角回答：现有表现能否让玩法被理解和验证？现在该补 UX、保留文字/混合形态，还是先验证图形切片？需要什么技术能力？
不是第五把尺子，不评价抽象“高级感”，不预设像素化或换引擎更好。沿用主 SKILL、[编排](orchestration.md)及[裁决](adjudication.md)；轮次 ID 稳定，R09 按调度在 R06/R07 前执行，并非评分之后。

## 一、调用、输入与只读边界

明确请求 UI/UX 取舍、表现形态、像素转段、引擎/平台路线时启用。文字/混合原型的完整里程碑默认检查体验适配与转段；普通局部功能迭代不自动展开引擎调研。
技术路线小节只在用户要求选型/迁移，或目标平台有待验证的硬约束时加载；没有此需求则写未启用，不为齐全推荐一批引擎。
输入：版本、主打体验、已有 R01–R05 原始证据、目标设备/输入方式、下一项玩法假设、阶段预算；有多个可玩切片则记录各自构建与规则差异。
技术输入另列：已有语言/资产/部署、单人或多人、离线需求、必须发布的平台、维护能力、构建与自动化约束。来自文档的内容标“项目声明”，缺的填未知，不从网页外观猜架构。
信息不得逆流到首访者。复用证据不算新试玩；只有文档/截图时只作可见问题分析和待验路线，不裁决全局好玩，不给分。
评审不安装引擎、不编写/改造游戏、不修改存档/时钟、不读取隐藏实现寻找玩法答案。切片制作、架构审查和构建实验交开发流程另行授权；有现成产物才实际验收。

## 二、先分开三条轴

在轮次头写清：**玩法组织**（单人/多人、事件/经营/空间/实时等）／**表现形态**（文字、卡片、符号图、像素、其他 2D/3D）／**发布平台**（网页、桌面、移动）。三者不得互相替代。
“文字”不是玩法类别，“像素”不是引擎，“客户端”不意味着必须图形化，“MUD 原型”不自动意味着需要多人服务器。用一次实际行动说明哪些信息和操作对主打体验必要。

## 三、体验适配检查（现象→测法→判定）

V 编号仅定位本视角检查；体验缺陷必须同时引用原四尺条款，由 R07 统一定级。下列级别均以适用条件和实测损害为前提；路线偏好与验证缺口不强填 P 级。
- **V01 当前情境与历史分工**：打开一个管理面板再回来，随后回读旧事件；能否指出当前位置、当前对象、可做动作和最新变化？只能翻整段历史重建当前状态 → P1（一C1/一A2、U9、T5）；实际破坏核心行动链才候选 P0（一A1）。不强制固定分栏或弹窗。
- **V02 情境—条件—行动—结果**：选两个现成选项，操作前找成本/限制，操作后核对变化及原因；氛围文字掩盖必需条件、不可用动作不解释 → P1（M1、U3、T2）；内容充分但措辞缺情境差异 → P2（W1/T5）。未知剧情可保留，不等于隐藏当前规则。
- **V03 渐进呈现**：对比开局与一次已测解锁，检查新功能是否有当下用途，旧信息能否找回；未来系统一次摊开导致关键入口无法辨认 → P1（U1/U6）；当前必用规则被藏到行动之后 → P1（M3）。只有开局资料就不宣称已验证后期展开。
- **V04 文字节奏与阅读控制**：触发连续消息、回读、返回行动区；强制逐字等待、自动滚动或重复刷屏实际妨碍读/选 → P1（T1/T5）。静态增量提示可以达标，不强制动画；暂停阅读不等于暂停多人世界。
- **V05 中文、视口与输入**：在声明支持的视口、缩放及输入方式下完成核心动作；检查正文可读、焦点、中文输入确认、长名称和动作区域是否被遮住。实际截断/错提交/无法操作 → P1（T6/U4/U6）；无设备能力标未测，不把代理读得快当真人可读。
- **V06 点击与命令的职责**：若同时提供按钮、快捷键或命令，在可比状态执行同动作并核对成本/结果；同名异义或入口提示不一致误导玩家 → P1（M1/U4/一D1）。只提供一种输入并非违规，不强迫实现双入口。
- **V07 空间是否真被验证**：走一段含返回的路线，或比较一次距离/邻接/布局相关选择，指出空间信息如何改变行动；有规则且导航信息不可读 → P1（T3）；已测核心空间选择不产生宣称的后果才候选 P0（G2）。尚未实现的走位/物流/射程无法由文字选项验证 → 验证缺口，不判玩法已失败或已通过。
- **V08 风格是否服务操作**：从研究附件选至多两个相关做法，逐项对照同一任务；终端小字、装饰卡片或像素字体造成实测辨识问题 → P1（U6/T6）；已可用但同类样式局部不一致 → P2。没有图块、插画或自定义主题不单独扣分；功能形态可以借鉴，不复制品牌或假称当前参照已试玩。
- **V09 跨形态接续**：仅有双方可玩产物时，对同一行为核对目标、选择、成本、结果、实体和原档接续；转图形后已确认规则/因果/上下文退化，按对应 G/M/U 条款提候选。仅有未来计划时列保留契约及未知，不声称能够无损迁移。
- **V10 发布与可测试性**：在已提供、可访问的目标构建验证打开、输入、一个安全动作、关闭重进和存档；产品故障按 B 类，体验损害按相关 U 条款。Canvas 没有 DOM 控件或当前代理无法录制是测试能力缺口，不自动是产品缺陷；有无障碍承诺则独立实测。没有客户端包，不宣称桌面发行通过。

## 四、先作三层投入决策

每项写“当前证据／不做会妨碍什么／最小改动或实验／重验条件”，不用统一工期或投入百分比。
| 层次 | 现在的处理 | 不允许的替代解释 |
|---|---|---|
| 理解与操作底线 | 当前行动所需目标、条件、反馈、恢复先补；有损害就入问题台账 | “转像素后一起解决”不撤销当前 P0/P1 |
| 玩法验证必需的表达 | 若核心假设依赖空间/时序而文字不能验证，优先安排最小地图或场景切片 | “三圈文字循环跑通”不证明动作、物流或空间玩法成立 |
| 装饰与制作深度 | 必要反馈已成立时，复杂动效、皮肤、自由面板编辑可列延后项 | 没做不是 P2；多做也不保证有趣 |

阶段建议允许组合：**先补最低 UX／继续文字或混合形态／先做图形验证切片／已有证据支持限定范围转段／证据不足待验证**。指出主建议、依赖和不采其他路线的理由。
不能以“还有 P1”禁止一切小切片验证，也不能以“图形看起来更正式”建议整项目重写。先修 UX 与探索图形可以分任务进行，不能在同一评审中边修边改变被测版本。

## 五、图形切片对照协议

1. 锁定一个代表流程：进入地点→理解问题→比较方案→行动→观察世界变化→接续。登记原假设、目标人群/设备、动作预算、通过与停止条件。
2. A 为最低可用文字/混合版本，B 为候选表达切片；规则、内容范围、起点及信息尽量相同。任一版本不存在就输出制作任务卡，不伪造对照结果。
3. 不能拿坏文字 UX 对比精修图形来证明“图形天生更好”。同时改变教程/数值/内容时逐项标差异，只能比较方案整体，不能归因于画风。
4. 使用独立新执行者/获授权的新档；不能隔离时标学习效应。真人可在不同参与者间平衡次序，代理不冒充真人样本；模型耗时不是玩家理解速度。
5. 比较理解错误、求助、有效选择、空间决策、阅读/操作接续和回报证据；技术及制作比较另记构建结果、实测改动记录/未知。不以截图美观、功能数量或想象工时选胜者。
6. 只在已测范围建议保留、调整或扩大切片；给撤回条件。小样本方向验证不声称统计显著、整体留存提升或完整成品成功。

## 六、技术路线是条件建议，不是引擎榜单

按需读 [表现与工具研究](../research/presentation-engine-notes.md)，具体平台/语言支持、版本、许可与部署要求在作建议时重新查官方文档，记日期与来源；无法联网标未核验。
先写必须支持的能力，再比“保留当前栈”与至多两个实际候选；分别注明多人服务端、叙事工具、渲染库、完整引擎、桌面外壳的职责，不能当同类一锅排名。
比较卡：`候选/版本/职责｜满足的硬约束及出处｜已有运行证据｜可保留的数据/协议/规则规格｜需要重写的代码/表现/工具｜成本来源或未知｜最大风险｜最小验证及退出条件`。
换语言不保证代码可复用；保留服务端不代表所有客户端同步已经解决；单人不因名为 MUD 就被迫联网。拆分规则/动作结果/表现只是候选契约，不从浏览器断言现有代码耦合。
AI 开发便利须由已授权的真实改动—构建—运行—取证记录支撑；有编辑器 API 或模型熟悉某语言不能证明生产效率更高。当前评审不自动获得编辑器/部署权限。
用户只给网页时，评审可列技术待验问题；不能确认吞吐、维护工时、原生兼容、存档迁移或构建成功。遇到能力不匹配先比较局部适配与保留方案，不能默认换引擎。

## 七、输出、去重与出段检查

仍按编排交 `rounds/R09.md` 六项短报告；其中必须有：三轴定位、V01–V10 覆盖、三层投入建议、转段主结论、可比切片计划/结果、按需技术卡。
当前缺陷使用 `R09-Fxx` 并引用原尺，交 R06 反证和 R07 唯一分级；引用 R02/R05 已有问题即可，不因换视角重报。
路线决策使用 `R09-Axx`，记录证据/假设/备选/取舍/最小验证/撤回条件，放本轮报告；未测系统在覆盖表，不能计入已确认 P0/P1/P2。
总报告第 6 节只接已裁决缺陷，第 8 节接临时方案及保留/重做/观察依据，第 9 节接最小切片或技术验证建议；不新增第十一节。无需技术选型时明确未启用。
转段标签继续描述既有问题/决策的延续性，不变成路线偏好的严重度；现有已验证亮点及其输入、反馈、存档契约须列为转段保护项。
R08 只评当前可玩体验：不因为选 Godot、改像素或计划迁移而加减分。建议实施后另开新 game_build/run，旧结论保留。
出段自查：有没有把风格当质量？把功能跑通当空间玩法已验证？把截图当动态证据？把工具打不开当产品缺陷？把选型建议塞进 P0？把缺客户端/图形切片写成已通过？有一项就修正或补证。
