# 多视角评审编排协议

本文件供总控调用；四把尺子和严重度以主 SKILL 为准。轮次是取证/判断视角，不是新的尺子，也不是必须从注册开始的多次完整试玩。
完整流水线：定靶 → R01 → R02 → R03 → R04 → R05 → 按需 R09 → R06 → R07 → 可选 R08。Phase 0–5 不变；各轮证据共同进入 Phase 2/3，R07 对应 Phase 4/5。
本文件定义代理执行契约，不自带浏览器、自动派生代理或定时运行服务；具体操作必须由宿主实际执行并留记录。

## 一、单次调用与模式路由

用户只需提供游戏入口/项目、评审意图和允许的测试身份；从已有上下文、获授权的项目说明取得其他字段，不重复询问。
缺非关键项显式暂定；没有入口、合法身份或必要授权，先交可完成的计划及缺口，不假装完成试玩。

| 请求 | 启用计划 | 必须保留的输出 |
|---|---|---|
| 未指定深度的验收 / 本轮迭代 | 改动相关 R02–R05；至少验证核心循环和相关数值；首次或引导改动加 R01 | R07、十节短总报告、未测项；有旧发现则回归 |
| 完整 / 里程碑 / 全部 / 多角度分轮 | R01–R05 中所有适用轮次；文字/混合原型加 R09 适配/转段部分；再 R06＋R07 | 各轮短报告、全覆盖台账、十节总报告；不足如实列出 |
| 单独首访 / 模拟新用户 | R01，必要时辅助对照，随后 R07 | 封存的无提示记录与首访范围总报告；其余视角未测 |
| 单独评分 / AI IGN | 先核验同版证据，缺口按相应轮次补测，R07 后 R08 | 同版诊断可引用不重写；证据不足为进行中/不评分 |
| 红队 / 更严厉 | 原计划叠加 R06；连续两次无主要设计发现也触发 | Phase 0 指控登记及支持、反对、证据不足的裁决 |
| 体验回归 | 相关固定路径＋必要的新盲玩＋R07 | 旧发现到新证据的映射；未验证不关闭 |
| 真人试玩方案 / 真人记录分析 | 仅在授权和真实记录范围内调用真人协议 | 方案或实证分析；不能模拟真人记录凑轮次 |
| 表现形态 / UI/UX 投入 / 像素转段 / 引擎或平台路线 | R09，按需复用或补测 R02/R03/R05，再 R06（有严重候选/争议时）和 R07 | 体验缺陷、验证缺口与路线决策分开；纯资料咨询无试玩裁决或评分 |

“完整评审”不默认发布评分；用户同时要求打分才启用 R08。单轮也是一次 run，只是多数视角不在范围内。

R09 是兼容新增的稳定 ID，不按编号排序：取证后、R06/R07 前执行。普通局部迭代不自动做引擎研究；技术部分须用户要求或有发布硬约束。R01–R08 职责不变。

## 二、先写 run.md：版本、权限、预算与能力

必填或明确标未知：
- 身份：`run_id`、日期与时区、`skill_version`（读取 VERSION）、`skill_commit`、`report_schema`、`critic_scale`（当前为 1）、`game_build`、阶段、目标玩家、主打体验、评分类型。
- 环境：真实入口/允许域名、视口/语言/输入方式、游戏账号及存档代号、模型/工具可见标识、截图/连续捕获/独立上下文/时钟/持久化的实际能力。
- 授权：测试存档是否可丢弃；登录、消费、失败、重置等允许范围；禁止付费、接触真实玩家或改生产数据的边界。秘密不写入简报、版本库或报告。
- 计划：本轮假设、启用轮次、所用条款、时间/动作预算、停止条件、补测预算、预期存档交接和未测处理。

版本未知不编 commit：记录界面版本、部署时间等可观察指纹及不确定性；无法证明两个样本同版，就不能作确定的跨版比较。
本次固定 skill 和游戏构建，途中不更新规则、不改代码。不受控部署发生变化时封存旧记录，新建 run 或清楚分段；涉及改动的旧证据不得用于新版确认。
记录墙钟、前台游戏时长、工具等待、记录开销和真实离线间隔；工具/模型耗时不能当玩家阅读时间。
资料型 R09 可在没有入口时交条件分析及待验计划，记为资料分析而非试玩完成；不豁免其他轮次的浏览器要求。
先检验页面打开、一个安全操作、状态反馈及证据保存；工具/网络/权限受阻不是游戏 P0。缺浏览器只出计划或静态观察，不完成动态裁决。

## 三、逐轮调用卡

| 轮次 | 给谁与何种输入 | 必做或复用条件 | 交回什么 |
|---|---|---|---|
| R01 新手首访 | 隔离执行者仅收 agents/blind-player.md、公开介绍和安全简报 | 新浏览器＋新服务端测试档；自由探索先封存，再目标任务/最少辅助 | 原始记录、理解链、停止原因、辅助差异；执行者不评级 |
| R02 交互操作 | 专项评审收任务情境、尺子一和相关 U/T 条款 | 实际打开/返回/取消/恢复关键路径，核验连续性与反馈 | 路径证据、摩擦及候选发现 |
| R03 核心策略 | 专项评审收主打体验、G/M/尺子三/四相关条款 | 核心循环三圈或声明不足；可比状态比较路线并寻找反例 | 机制卡、策略差异、核心循环与候选问题 |
| R04 经济与回访 | 专项评审收 I/N/节奏条款、保存边界及原档代号 | 有相应系统才测产耗/瓶颈；原档离开再回来，记录真实间隔 | 净速率、时间墙、结算/接续证据；长期不足未测 |
| R05 世界与文字 | 专项评审收 W/T/M2 相关条款和可见叙事承诺 | 已承诺世界变化追踪、路线理解、阅读接续；无角色叙事不强加 | 地点/事件/阅读证据、主打表达及候选问题 |
| R09 表现适配与转段 | 专项评审收已封存的相关体验证据、下一玩法假设、设备/阶段约束，读 presentation-transition.md | 先诊断最低 UX，再定位空间/时序验证缺口；已有切片才做对照，技术选型按需核查 | V01–V10 覆盖、R09-F 候选、R09-A 路线决策、最小验证/撤回条件；建议无 P 级 |
| R06 红队复核 | 复核者收 Phase 0 已封存指控、候选问题与原始证据 | 优先核验候选 P0、关键亮点、冲突；每个候选 P0 尝试最强反例 | 指控裁决、支持/反对证据、待补测；不得凑 P0 |
| R07 综合裁决 | 总控收全部轮次和原始证据，读 adjudication.md | 核验、去重/关联、冲突补测、最终分级和覆盖汇总 | 唯一 findings.md、十节 report.md、回归卡 |
| R08 媒体评分 | 评论员收锁定范围、已核验证据、最终问题/亮点，读 critic-scoring.md | 不先收期望分或旧分；编辑先作文字判断，之后核对分歧 | critic.md；暂评/完整版本/不评分明确标识 |

R01 主持/分析者可在记录封存后提出候选发现；不能让执行者为了报告条目去逐个搜按钮。
R02–R05 可复用已有同版原始证据，但每条结论必须检验是否覆盖本轮的条件；原始证据未覆盖的动作必须补做。每轮注明“新操作 / 复用”，复用不算多次复现。
R09 仅复用/补取当前版本证据，不制作游戏切片；单独发起路线咨询时可先资料分析，不能反向传给未封存的首访者。
R04 的回访若需真实等待，可在不触碰原存档的独立环境完成 R05，记录顺序调整原因；默认串行，不通过改时钟或模拟新局跳过等待。当前预算不足就未测，不承诺后台续玩。

## 四、信息隔离、状态交接和停止

总控保留设计文档、评价尺子和原假设；净化后才交给首访者。历史上下文自动继承时记“受限黑盒探索”，不能一句“忘掉之前内容”就标独立新手。
专项初评前不互看尚未封存的观点和候选分数；共享事实允许，分享原始路径会影响独立性，必须记录。需要复现旧问题时明确为定向复验，不再声称盲测。
同一存档一次只有一个操作者；交接记地点、资源、未完成目标、保存时点、阅读/输入上下文、已获提示。对照策略用授权废档和可比状态，不擅自修改存储造状态。
每轮状态仅为 `未开始 / 执行中 / 已完成 / 部分完成 / 阻塞 / 不适用 / 未启用`；已完成只表示计划执行完，不表示游戏通过。
达到预算、授权边界或同一阻塞三种合理尝试仍无信息时封存；正常冷却不算阻塞。没有入口证据时不无限重试；无法触及的后续系统标未测。
版本改变、存档污染、独立性失效、证据文件丢失应立刻记入 run；补测有上限，优先解决最可能改变 P0/总评的争议，不一直讨论到“意见统一”。

## 五、统一分轮输出：短报告，不重复十节

`rounds/Rxx.md` 固定六项：轮次/状态/输入边界；目标和实际覆盖；新操作/复用证据索引；观察与本视角结论；候选发现及亮点；未测项、停止原因和交接。
引用证据使用本次唯一 ID，如 `E-R01-001`，附真实文件路径及视频时段；新增复现使用新 ID。路线决策为 `R09-A01`，存于 rounds/R09.md，由总报告第 8/9 节引用；路线建议不计入 P0/P1/P2。候选发现为 `R03-F02`，字段采用统一裁决协议；R01 原始记录保留而不填级别。
覆盖逐条交 `条目ID / 符合、违规、未测、不适用 / 条件 / 证据 / 理由或补测`；疑似问题仍是候选，不擅自标“确认违规”。
无新操作但合格复用时明确说明；只读其他人的摘要不能标本轮完成。
每轮结尾检查：记录是否封存？可追原始证据？是否越过输入/权限边界？把未测/复用/假设标清了没有？

## 六、报告包与模块交接

授权后存入被评游戏项目的 `docs/reviews/<game-build>/<run-id>/`，不默认写进 skill 仓库：
`run.md`、`rounds/`、`evidence/`、`findings.md`、`report.md`、`regression.md`，评分时另有 `critic.md`。
未授权归档时按同名会话分节交付；证据链接仍须真实可访问，不伪造文件已创建。
总报告只一份十节，使用最终问题 ID；各轮旧判断不可覆盖删除。原协议中的“十节输出”在多轮下指整次总报告，不要求每个子代理重复生成。
真人证据按同版、授权、匿名条件进入相应视角；与 AI 的分歧交 R06/R07，不投票。缺真人只记录未开展或输出主持方案。
R09 的未来方案不计入当前媒体分；没有图形/客户端产物只能交计划。原版缺陷与迁移后的实际回归分别保留版本及证据。
R08 新发现事实错误时先交 R07 核验并刷新台账，再定稿评论；不能只在媒体文章里秘密改结论。修复建议变成回归卡，修改后另开新版 run。
每轮与总报告引用相同 skill/游戏版本；无法取得提交 SHA 时如实写未知及来源，不用 VERSION 数字伪称完整可复现。
