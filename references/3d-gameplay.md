# 3D 空间与操控体验评审（R02/R03 按需附加检查）

本视角回答：可玩 3D 构建的镜头、空间可读性与操控，能否让玩家理解并完成主打行动？这是玩家视角的设计与体验检查，不评引擎代码、资产制作或性能优化，不新增尺子、轮次与 schema，也不是必选升级路线。沿用主 SKILL、[编排](orchestration.md)及[裁决](adjudication.md)。空间能力按 [能力对照](capability-review.md) 的模块行登记：参照实现 → 目标提供/缺/替代 → 玩家能力结果；TD 用于定位具体损害与深度取证，不新增台账。
TD 编号只用于定位本视角的检查项与覆盖登记；当前镜头与操控缺陷仍按 TD＋原尺形成候选（设计问题 D 类），经 R06 反证、R07 统一去重与定级，不因改叫“建议”而移出活跃缺陷；只有未来表现形态或技术路线建议走 [表现适配与转段](presentation-transition.md) 的 R09-A，不计入 P0/P1/P2。

## 一、调用条件与适用登记

- **何时加载**：宿主提供可玩 3D 客户端（Web 或原生）并做相关评审，或用户明确要求 3D / 镜头 / 空间操控评审时加载。只有计划、截图或资料时只输出待验方案与验证计划；图形不存在就标未测，不判已测。
- **加载范围**：完整 3D 评审加载适用项；局部评审（如仅看镜头或建造）只加载相关 TD 项，其余标未启用；未启用不等于不适用，专项没启用不豁免相关条款。
- **不强制升级**：2D / 像素 / 文字→3D 不是必选转段；灰盒与原型不要求完整素材和动画，但仍须玩家可理解的空间与行动反馈，“没有美术”不等于“空间不用验证”。
- **未提供与已承诺**：没有自由相机、没有战斗、没有跳跃或载具等未提供功能不强求、不判缺陷，但仍须在能力对照行登记有无、替代或合理省略理由（[能力对照](capability-review.md) Cxx 仅定位），不因未提供让相关能力行消失；同类任务必要但未宣称的空间能力（如选址、观察所需的平移、缩放、俯仰）照查。替代成立须按 [能力对照](capability-review.md) 第七节取正证据（同任务、相关不同局面与最强不利例），有意创新不自动成立；单次例、人体未知与执行故障（B）分开。未来假设的系统记验证缺口。但当前版本已向玩家承诺的行动链（教学、目标、介绍或现有玩法依赖的空间行动）实际缺失或走不通，仍按原尺实际损害评，不能用“未提供”免责。
- **轮次承载与隔离**：由既有 R02（镜头/输入/辨识/UI）与 R03（空间选择/策略，战斗仅存在时）承载，必要处补 R04/R05；R06 反证、R07 去重裁决。R01 只收角色卡与净化简报，不给 TD 判据、不泄露路线、镜头答案或正确走法。
- **与文字 / 2D 评审的关系**：空间信息以文字式描述承载时用 T3 与 R09 的 V07 定位，不把文本检查冒充 3D 检查；转段后按 [体验回归](experience-regression.md) 重验输入映射、镜头与空间线索。
- **体裁组合**：可与体裁附件叠加；模拟经营类 3D 构建按需组合 [模拟经营专项](management-simulation.md)，其参照另读 [经营基准](management-baseline.md)，同根问题只计一次。

按相机形态登记适用性，同一构建有多种相机时分别记录，不把一种模式的结论外推到另一种：

| 相机与镜头 | 重点检查项 | 登记口径 |
|---|---|---|
| 第一人称 | TD01 回正与转向、TD02 视野、TD04 相对输入、TD09 动态辨识 | 视向自由度低不等于豁免；不要求常驻旋转 |
| 第三人称 | TD01 目标追踪、TD02 遮挡与恢复、TD06 交互选中 | 镜头与角色运动的关系是主要检查对象 |
| 俯视 / 策略相机 | TD01 平移/缩放/选址视角、TD03 深度线索、TD06 选择目标、TD07 导航、TD08 空间策略 | 高低差、射程与覆盖范围仍按实际动作测 |
| 固定镜头 | 按既有跟随 / 切换规则测；缺旋转不判错 | 判定依据是可见性与恢复，不是构图审美 |
| 自由镜头 | 增设视点改变与回正测试 | 不因“能转”就假定追踪与遮挡问题不存在 |

## 二、动态试玩前提与只读边界

- **可裁决前提**：操作对象须是宿主实测能打开、能操作、能连续观察，并取得足以支持对应断言的证据（截图、录制或时序数据）的客户端；达到即可测试相关动态，不要求短演示同时具备存档能力。无法实际控制的客户端记能力阻塞或在覆盖表写未测，不据外观推断游戏缺陷，也不默认必须换引擎（能力缺口写法参照 R09 的 V10）。
- 具体工具名不保证存在：用现有等效浏览器或客户端操作 / 捕获能力并声明限制，不虚构调用；工具抓不到画面按未测记录。
- **只读边界**：不安装引擎、不直接改写存储 / 存档、不改时钟；游戏代码与配置只读，不擅自用设置覆盖配置；允许正常试玩改变授权的测试档，游戏内已提供的控制与菜单可正常操作；不付费、不接触真实玩家。
- 每次会话登记视口、语言与输入方式，以及截图与连续捕获的实际能力，缺什么就压缩对应断言；玩家任务含长期投入、积累或跨会话时，保存与接续即候选核查（无宣传也查）：真实无法测试记未核验或覆盖未测，仅确实当前不需才不适用。
- 真实测试录制不能摆拍、拼接或冒充；合成示例、演练与推测必须标明；实测没有发生的事不写成已确认。

## 三、检查项 TD01–TD10

- **TD01 观察与相机：平移 / 缩放 / 旋转 / 俯仰、跟随与回正**
  - 适用：任何已提供的相机模式；固定 / 2D 概览可用固定视角与图层核对等效完成同一批任务，不强制自由镜头；不强迫可旋转，固定镜头按其既有跟随规则测。
  - 能力登记（先于动作）：平移（pan）/ 缩放（zoom）/ 旋转（rotate）/ 俯仰（pitch）逐项在行内登记具备 / 部分具备 / 已确认缺失 / 未核验（对照 [能力对照](capability-review.md) 四态）及替代与来源；无该项照记，不自动免责；只对实际提供的动作执行测试。
  - 动作：大场景定位（平移＋缩放）、小场景细节核对（缩放）、高低 / 多层选址与遮挡（旋转 / 俯仰）、对象查看与选中前可见性（objects 任务），以及一段含转弯、狭窄处与一次视点改变的路线；记录维持可见所需的额外调整次数。
  - 观察：镜头是否持续给出行动所需视向；目标在转弯与调整中是否实际丢失，丢失后能否回正或恢复。
  - 判定：频繁修正或丢失不可恢复并妨碍行动 → P1（一B1/U4/F4）；风格偏好不计缺陷，只有表达不足且有原尺证据（如 U6）才按 P2。
- **TD02 遮挡、视野与信息可见性**
  - 适用：有遮挡物、转角或高低差的场景。
  - 动作：接近障碍、过转角、上下高度变化时，分别观察角色、交互物、危险与标记能否被识别。
  - 观察：被遮挡后是否有实际恢复机制（按构建提供的镜头避障、轮廓、声音或标记等）。
  - 判定：决策时关键对象持续不可识别且无恢复 → P1（U3/U6）；确认遮挡使核心行动链、控制或主打体验不能成立，经 R06 反证后可候选 P0 并回接适用条款（如 F4、一A1）；单次失败不判 P0；固定构图的审美差异不判错。
- **TD03 朝向、距离、高度、尺度与深度线索**
  - 适用：有依赖空间预判的实际动作（走位、跳距、覆盖范围、射程等）。
  - 动作：在可比条件下先预测（能否走到 / 跳过 / 打到）再执行，比较预测与结果。
  - 观察：构建提供的线索（网格、影子、指示器、辅助线）是否足以支持一次正确预测。
  - 判定：已提供动作缺可读线索、预测系统性落空并影响行动 → P1（M1/一B2/F6）；主打体验完全依赖空间预判而线索不可建立，反证后候选 P0（按适用性回接 F4 / 一A1 / G2）。
- **TD04 移动、镜头相对输入、转向与可预测性**
  - 适用：实际支持鼠标键盘 / 手柄等输入方式才测，不假设未提供的设备。
  - 动作：同一动作在改变视点后对照执行，记录输入到行动的映射与设置可知性。
  - 观察：转向与移动是否可预测；稳定惯性、设置未知与操作故障三者要分开。
  - 判定：转向与移动不可预测并实际妨碍行动 → P1（U4/M1/F4）；设置不可知本身不判错，只在妨碍行动且无法查明时计 P1；稳定可学、受支持的惯性是设计选择，不判缺陷。
- **TD05 通行边界、垂直空间、跳跃或载具**
  - 适用：只测构建实际支持的移动（走、跑、跳、攀爬、载具、传送等）。
  - 动作：按实际场景采样普通玩家动线，遇到阻挡、边缘、上下层或落点就记录；不强求同一处同时有能过与不能过的样例，也不强求测遍垂直空间。
  - 观察：阻塞边界能否辨认与恢复；垂直空间与落点的通行规则是否有可理解反馈。
  - 判定：边界辨识问题按摩擦 P1（U8/M1）；确证设计规则使主打循环无路可续，反证后按原尺核心条款候选 P0，不因“不可恢复”机械降 P1 或机械升 P0；穿模、卡死等碰撞执行缺陷按 B 类技术故障单列，不升设计 P0；规则体验问题按设计 D 类判；不做 exploit 与越界攻击测试。
- **TD06 场景交互、选择目标与拾取 / 建造 / 放置 / 瞄准**
  - 适用：构建实际提供的场景交互方式。
  - 动作：在邻近、相距较远、多个对象相邻三种条件下各做一次交互，检查选中与误触。
  - 观察：选中对象与预期是否一致；状态、成本与结果的反馈能否指认。
  - 判定：难以选中、误触高频且无防错、成本结果不明 → P1（U6/U8/一B2）；核心交互或建造循环被选中混乱破坏，反证后候选 P0（按适用性回接 U1 / G2 / M1）。
- **TD07 关卡导航、地标与返程**
  - 适用：有可探索空间与可辨识地理。
  - 动作：选一条含一次选择与返回的路线，记录实际空间信息（地标、光照、布局、地图）、选择代价与结果，再复走一次对照。
  - 观察：能否据实际信息复述路线并返回。
  - 判定：目标 / 规则或导航线索难辨但可推进 → P1（按适用引 U4/F5）；因入口或规则始终无法建立推进链 → 候选 P0（U1/F5/G1 的核心条件，须反证）；实际空间选择无后果才引 G2；T3 仅在空间由文字式描述承载时引用，一A2 仅在真正返回面板上下文时适用。正常探索或刻意隐藏内容的无提示不自动判错；不拿“场景很大”当深度；未测区域保持未测；首访信息不向 R01 泄露。
- **TD08 空间策略、遭遇、掩体与敌我信号**
  - 适用：已有战斗 / 威胁 / 对抗内容才测，不要求每款有战斗。
  - 动作：用可比起点或授权的独立测试档，在同一遭遇比较两种战术（绕侧 / 正面、掩体 / 高低差等），再观察一个相关第二局面；记录起点与条件差异，不擅改档，第一次击杀导致第二局面不可比时如实标注或改用独立档。
  - 观察：敌我身份、危险区域与掩体有效性是否可读；死路或惩罚是否有预告与恢复。
  - 判定：分级按 G2/G7/G8/N2 原有级别；没有战斗不判缺陷，没有敌方 AI 不测其适配。
- **TD09 动态辨识、运动舒适与设置**
  - 适用：有前台运动、动作特效或镜头设置。
  - 动作：在对照动作中按实际提供的前台状态与设置，观察快速运动中关键信息能否识别、设置是否真的可控有效。
  - 观察：运动过程中危险、目标与状态是否仍可辨；镜头设置变化对其的实际影响。
  - 判定：实际妨碍行动 → P1（U6，动态断言取证见第四节）。没有人体证据不宣称测到眩晕或真实舒适度（铁律 11）；没有音频能力不否定空间声音；舒适度与真人校准指向 [human-playtest.md](human-playtest.md)。
- **TD10 空间行动的中断、菜单叠层与接续**
  - 适用：支持设备与视口下的核心空间动作。
  - 动作：构建已提供菜单或叠层时才开关测试，核对原对象、目标、镜头与输入锁定是否恢复；玩家任务含长期投入、积累或跨会话时，原档接续即候选核查（无宣传也查），未找到入口或无法测试记未核验、不编造动作也不判全局缺失，仅确实当前不需才不适用。
  - 观察：能否回到原行动上下文；构建已有的暂停与自由鼠标规则是否自洽。
  - 判定：状态丢失、输入被吃掉或错过必须处理的局面 → 按 一A1/一A2/U9 原级判；战斗不总是要求世界暂停，按该构建已声明的规则判。

## 四、证据记录卡（每次动态断言至少记录）

- 构建与档：`game_build`、存档代号、场景起点与目标；
- 相机与视向：相机模式、起始视向、关键对象可见状态与遮挡判断；
- 输入：实际设备的按键 / 鼠标映射与设置（记录所见，不猜轴数、不推断未提供设备）；
- 动作链：连续动作与顺序、操作前预测及来源、实际操作、实际因果与延迟；
- 捕获：画面时间片（连续录制区间，或足以证明该断言的时序数据）、捕获能力与失败点；
- 复验：恢复后的状态、最强反例尝试与结果。

实时时序用连续屏幕记录或能证明对应断言的时序数据，不用离散截图否定短动态；没有内置坐标不猜世界坐标；没有帧率测量不编 FPS，也不把工具或主机异常归因到游戏。记录目标与镜头变化便于复验；不建“必须上传所有视角”的大流程，覆盖不了的动作写未测。

## 五、判定与分级（回接原尺）

- 不新增 3D 评分表：摩擦按 P1，只有核心循环、空间策略或主打承诺被证伪才候选 P0，行动已成立后的表达问题按 P2；碰撞等执行故障按 B 类单列，不因阻断自动升设计 P0。
- 回接条款：镜头 / 输入 / 辨识 / UI 用 一A/一B/一D、U 与 F；空间选择、战术与数值用 G/M/N；机制因果用 M1/N2；T3 仅在空间信息以文字式描述承载时引用。
- 覆盖结论沿主协议逐条记 符合 / 违规 / 未测 / 不适用，不用“已测”代替符合与违规的分别结论；不适用须有体裁或功能理由，未启用只是范围与轮次状态、不等于不适用；工具、权限、时间不足一律写未测，不拿未测当符合。
- 完成条件：已加载的 TD 项都有适用条件、实际动作、证据与结论，或注明为何不能测；未提供且不适用项有理由。不要求覆盖所有相机模式或所有视角才算完成。

## 六、输出、合成示例与保护项

- 输出沿用 `rounds/Rxx.md` 六项短报告：候选用 `R02-Fxx` / `R03-Fxx`（必要处 R04/R05）并同时标 TD 编号与原尺条款；R06 反证、R07 去重后进总报告第 5/6/7/9 节与体验回归卡，不新增报告章节。
- 亮点与转段：已验证成立的镜头与操控设计按 L 编号保留证据与回归检查；转段或修复后用 [体验回归](experience-regression.md) 的固定路径加新盲玩重验输入、镜头与空间线索，只跑固定路径不能关闭首访问题。

**合成示例（非实测，仅示区别，不得当已确认发现）**

- 示例 A · 抓不到画面：工具只能取离散截图，无法证明角色在转角的短暂遮挡会造成决策失败 → 记未测（一B4），不写“角色会消失”或“遮挡是缺陷”；连续录制到实际丢失与恢复后再判。
- 示例 B · 故障 vs 设计：角色能穿过一扇外观与宣称都表示应关闭的门，按 B 类执行故障候选；“穿门”本身不必然是 bug，先对照可见宣称与规则。主路线被隐藏墙阻断且玩家确切无法续接时，按原尺影响定级（如 M1/U8 摩擦 P1，或核心行动链不成立时按对应核心条款）；规则证据不足、无法区分 B 与 D 时记待确认，不合并两类、不因更严重或更丑改级。

出段自查：是否把风格偏好当缺陷？把一次采样当全局？把工具限制当产品问题？把路线建议塞进 P 级？把未核验误判为缺失，或对未提供功能直接跳过能力行？有一项就修正或标未测。
