# 新用户首访盲玩协议

仅在首访请求、引导改动或里程碑首访轮加载。主评审仍遵守主 SKILL 的证据、阶段和十节结构；本协议补充信息隔离，不增加第二套严重度。

## 一、分工与入场检查

主评审读文档、锁定假设、配置安全环境；盲玩执行者只读 [最小角色卡](../agents/blind-player.md) 和净化简报；裁决者在记录封存后对照四尺。
新建会话不等于独立真人。能创建不继承历史的子代理才称“信息隔离”；宿主自动注入旧对话/skill 时必须标污染。没有隔离能力则做受限黑盒探索，不宣称新手盲测。

| 主评审保留，不下发 | 可下发给执行者 |
|---|---|
| 本轮假设、达标条件、原始策划、往期发现、正确路径、评分尺子 | 入口、公开介绍、安全身份/存档、视口/语言、工具、预算及权限边界 |

首次访问使用全新浏览器上下文；同时核查账号、服务端存档、教程与解锁状态，不能只清 cookies 就说是新玩家。准备新废档须获授权；不得清空原玩家资料。
回访必须使用原档，记录离开/返回时间；账号凭证和持久化认证状态只存安全本地位置，不提交仓库。注册无法安全完成则记入口阻塞，绕过后只能称“登录后的首访”。
视觉路径只用可见信息；键盘/辅助技术另开路径并注明感知方式，不能把整棵无障碍树的读取能力当作视觉可发现性。

## 二、先自由探索，再做目标任务

默认无提示自由探索 5 分钟，可延至 15 分钟观察首圈；这是操作预算而非统一合格线。主评审预先记录实际游戏时间、工具等待和记录开销的区分方式，不能事后改预算让结果通过。
自由阶段只给入口，不提前指定“去探索、买食物、建房屋”等游戏目标；用户主动给出的真实入场目标可以保留，但须声明这不是无目标首访。
封存后才给 1–2 个目标式任务。任务写情境与结果，不给菜单名和点击步骤；独立评估任务可发现性须换新执行者/新废档，连续进行时标已经学习。
示例（仅在相应系统存在时使用）：“你准备离开当前地点，希望不会因准备不足被迫返回，请自行准备。”不能写“打开背包买三份食物，再点地图”。
任务提示包含的概念也可能提供线索；保存任务原文，辅助前后的结果分开，不覆盖自由探索的失败记录。

## 三、记录理解链，而非只记点击成功

| 节点 | 证据动作 | 不能替代它的东西 |
|---|---|---|
| 进入 | 自行通过真实入口到达可玩状态 | 开发者直接打开内部已登录页面 |
| 首次行动 | 自己发现可操作对象并得到结果 | 工具列出了一个可点击元素 |
| 理解因果 | 对下一次同类行动预测，再用操作验证 | 复述一段说明文字 |
| 有意义选择 | 比较并采取一个有不同成本/后果/表达的方案 | 首次点击“领取” |
| 自主目标 | 根据局面选择下一步并开始做 | 主持人或任务脚本指定下一步 |
| 自主续圈 | 第一圈后继续有具体行动与回报依据 | 文档承诺后面内容很多 |
| 返场接续 | 原档中定位旧计划、变化及下一步 | 新建一局重新教学 |

每个节点记 `已观察 / 未观察 / 尚未到达`、证据编号、前置条件和是否受提示。未观察的兴趣不等于确认没有兴趣；代理日志不生成玩家流失率。
可记录首次动作/选择/目标的实际时点，但必须带时间构成；不同模型的 token、墙钟时间与真人阅读时间不可直接比较。

## 四、卡住后做最少辅助对照

主评审在开始前给出停止规则；默认同一阻塞尝试三种合理操作仍无新信息或预算耗尽时暂停，不把真实冷却中的合理等待算成阻塞。
1. 封存无提示记录：最后理解什么、试过什么、缺什么、停止理由。不得为了补齐报告要求其继续猜答案。
2. 逐级帮助并逐字记下：先指向已存在的游戏内信息；仍不够时解释一个规则；最后才给具体动作。每次只补最少内容。
3. 辅助后观察一次可迁移的类似任务和下一圈；只会复刻主持人的点击路线，不算理解规则。
4. 帮助后能独立规划/探索，形成“入口或理解障碍”的线索；已知规则仍无有效后果，继续验证核心玩法。两者都须四尺证据，不以单次辅助推断因果已经证实。

## 五、MUD 追加实验（自由记录封存后执行）

- 世界记忆：改变一个承诺持久的对象/地点，离开再回来，指出变化及新行动；分清“日志说成功”“状态保留”“后果真正改变选择”。
- 阅读接续：回读旧事件 → 新消息到来 → 打开管理面板并调整 → 返回 → 原档回访；检查阅读位置、输入对象、当前地点与待办是否可找回。
- 阅读路径：分别测试按需求查信息和主动细读；不读全部背景仍能开始行动，愿意细读则能取得相应世界/选择信息。两条是压力测试路径，不是假造的用户群体。
- 首访任务与深玩样本分开编号；同一卡点熟练后消失，只能新增熟练路径证据，不能撤销新手发现。

## 六、输出与裁决

交回净化简报、实际隔离状态、原始操作日志、节点表、无提示/辅助对照和未测项。主评审再形成发现：现象 → 体验影响 → 四尺条款 → 置信度/级别 → 复验条件。
材料并入主报告第 2/5/6 节，十节仍保留，非本轮范围标未测；只有确实观察到卡点才生成相应体验回归卡。
不把 AI 轮次人数化，不编退出意愿；没有用户试玩资料不能补写“用户纷纷表示”。

## 七、方法出处与边界

浏览器隔离参考 [Playwright：Isolation](https://playwright.dev/docs/browser-contexts)；认证资料保护参考 [Authentication](https://playwright.dev/docs/auth)。
无路线暗示的任务写法参考 [NN/g：Task Scenarios](https://www.nngroup.com/articles/task-scenarios-usability-testing/)；学习目标与行为证据参考 [Player Research](https://www.playerresearch.com/learn/getting-more-from-usability-testing-your-game/)。
具体预算、停止规则、代理角色卡与辅助层级是本仓库的工程化约定，不是论文验证的人类行为模型。
