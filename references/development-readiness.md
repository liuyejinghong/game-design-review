# 开发准备度与材料审查（总控前置）

本附件承接早期路线：材料层必要能力与设计自洽 → 最小可玩核验（按依赖限范围）→ 现有深测 → 交接独立复验；服务新游戏、机制样机、交互原型、MVP 与开发中版本的评审请求。AI/个人开发是使用场景不是重定位，通用跨体裁能力对照主线不变。总控在首次评审、没有可靠基线或收到材料/设计评审请求时先读本文件，再进 [能力对照](capability-review.md)；四把尺子、Phase 0–5、R01–R09、十节报告、矩阵四态五值与 P 级全部保留，不新增轮次、尺子、报告章节、矩阵拆分或第二问题台账。

- **局部迭代**：已有可靠基线时只重查改动及其依赖，同版原始证据按原规则复用，不重做全量材料与参照调研，不沿用受改动影响的旧结论。
- **深度或评分请求**：先核最低前提（构建可打开、授权、工具能力）后直接进现有适用轮次；同版已核原始证据可复用，不把“构建可打开”强成当前必须再启动才评分——证据足够就直接核来源与范围，缺真实依赖才安全补测；无授权不能当前操作，但不阻已有合格证据的分析，推荐/评分范围按 [非官方评分协议](critic-scoring.md) 限定。最低前提不满足只缩小或暂停相应断言，不强制先补完整材料。
- **没有可玩构建**：仍真实完成材料审查并交付结论与最小下一步，不允许只回“不能试玩”；动态、全局裁决与评分的限制按主协议不变。

## 一、证据类型与支持范围

| 证据类型 | 可支持的结论 | 不足以支持的结论 |
|---|---|---|
| 设计材料 / 原型说明 | 规格矛盾、未决需求、当前声明与验证计划 | 运行时确实没有该能力、实际乐趣已失败 |
| 实际玩家端运行 / 时序 | 特定构建、状态、输入下的行为与影响 | 未测设备、全局最优或长期动机 |
| 工程检查 / 自动测试 | 实现接入线索、某测试条件的结果 | 陌生人能发现、真实手感或体验达标 |
| 真人研究记录 | 对实际参与者、任务与样本范围的观察 | 全体玩家普遍感受、未经测量的留存 |

四类不是可互换的高低等级；每条声明写证据支持范围，材料缺失与实现缺失分开，一次成功不覆盖失败恢复。

- 确认规格矛盾须给确切材料版本、声明原文、前提与反例；仅材料没写记“材料未交代”，实现与玩家端状态仍是未核验，不能纸面判 D/B/P0/不好玩。
- 已有玩家端或可见静态证据的真实损害才按原尺走原协议；研发方便（好实现、作者说明）不证明体验成立。
- 材料层不读隐藏实现给首访答案；工程核查是可选项，须获授权、只读、与首访执行者隔离，结果只用于缩小未核验、定位接入与形成任务，不默认升级为代码审查。系统性架构/管线核查（SA01–SA08）不在此展开，由 R09 统一承载（见 [系统架构与内容管线](system-architecture-pipeline.md)）；本节的隔离规则只管接入线索，不是 SA 的提前执行，工程静态卡也不混入材料审查段或玩家运行状态。

## 二、材料审查记录（run.md 唯一落点）

材料行的固定落点是 `run.md` 的 `材料审查` 段，沿 [能力对照](capability-review.md) 的 C 行稳定定位复用；报告第 2/5 节只引用，不重建。每条字段：

```text
C行｜玩家任务与必要性（玩法依赖、投入、目标玩家、平台、当前承诺、匹配参照）
阶段要求（本阶段必要／下一目标前必要／增强候选／合理省略，可暂定并写理由）
材料状态（明确设计／设计部分明确／材料未交代／不适用）
材料结论（规格矛盾，或待决/可验证假设及前提）
材料证据ID与原文定位｜最小下一步与玩家端补测
```

- run 材料段不复制矩阵运行状态或 findings 关闭状态，与第 5 节矩阵各写各的维度。
- 未形成 C 行的跨模块规格风险：先关联涉及的 C 行、材料证据与触发条件，不新增问题等级或第二台账。
- 本次没有实际材料项时，如实写“无材料／本次未开展及原因”，不伪造齐全。

## 三、验证范围决定（run.md 必有段）

对每组共享依赖的本轮活动写一条，字段：

```text
目标｜依赖条件｜来源C/D/B或关键未测项及证据｜条件状态（已证实缺口／未核验／已满足）
决定（继续／限范围继续／暂停相关环节）｜受影响活动｜仍可做什么｜最小下一步｜复验条件
```

- 这是任务路由视图，不是发布认证、新严重度或新问题 ID。
- 未知能力只暂停依赖它的验收结论，仍允许安全定向探测去核验该能力本身：保存状态未知不能禁测保存；没有接续只阻跨日验证，不阻镜头与操作检查；无关 P1/P2 不挡深测；只有无授权或不可操控才停止相关动作。
- 玩家目标必要能力未宣称也照查；没提供传统按钮仍记录能力有无、等效实现或合理省略理由；能力实际满足不要求传统实现。

## 四、候选能力契约（CAP）

每条两行：必要条件、材料要问、最小玩家端动作或允许替代。CAP 是测法条款，不是 D 问题编号；材料不存在不等于实现不存在；完整评审查适用项，局部只查改动及依赖。

- **CAP-01 进入与开始**：必要——作品要交给目标玩家独立使用。
  材料问：真实入口、开始/继续条件、支持环境是否明确，是否依赖作者后台操作；最小动作：从正常入口到达可行动状态，无账号不强求注册、无主菜单可直接进入。
- **CAP-02 首访学习与求助**：必要——新规则或新输入需陌生人理解。
  材料问：玩家如何发现第一步、理解结果、受阻时取线索；最小动作：无提示路径加一次规则迁移，场景示范、渐进提示可替代教程关，不因无教程按钮判缺。
- **CAP-03 受理、结果与状态**：必要——行动结果影响后续行为。
  材料问：成功、拒绝、处理中、结束如何区分；最小动作：操作与前后状态可对应，文字、声音、视觉均可承担，没有音频能力不否定声音。
- **CAP-04 核心规则与主打价值**：必要——所有受评核心，按体验结构变化。
  材料问：承诺的策略、发现、表达或叙事后果由什么规则产生；最小动作：验证一段主打体验，不同选项不强制数值收益不同，线性体验不强求分支。
- **CAP-05 模块连接**：必要——玩家任务跨多个系统。
  材料问：输入输出、资源流、对象状态与解锁条件是否接上；最小动作：完成一条跨模块路径，能买不能用、能放不参与规则要有证据，不凭图标推断。
- **CAP-06 推进、成长或终局**：必要——体验需要阶段变化、再参与或结束。
  材料问：第一段之后发生什么、成长如何使用、短作品如何明确结束；最小动作：至少走到相关节点，收藏、叙事、表演、明确终局可替代数值成长，不要求无限续圈。
- **CAP-07 中断、成果保护与接续**：必要——投入超出一次短局或跨会话积累。
  材料问：保存对象、触发与失败、恢复边界、可能损失是否定义；最小动作：授权档正常离开再返回核对关键状态，自动保存/检查点/持久世界可替代手动存档，短局可省持久保存。
- **CAP-08 失败、重试与恢复**：必要——存在失败、阻断或不可完成状态。
  材料问：原因、代价、退出与重试规则是否清楚；最小动作：在废档执行一次适用失败及后续路径，永久死亡可成立，不强制撤销或无限复活。
- **CAP-09 成本、取消与不可逆行动**：必要——有消费、建造、选择或删除等代价。
  材料问：是否知道作用对象与后果，确认和撤销如何匹配风险；最小动作：走正常提交、取消或拒绝路径，低风险不强制层层确认，知情高风险不强制全额退款。
- **CAP-10 输入、空间与导航**：必要——存在对应输入或空间任务。
  材料问：能否看清、选中、定位、移动并恢复控制；最小动作：在支持设备上完成代表任务，固定视角、地图层可替代旋转俯仰，2D 不以 3D 功能数量判差。
- **CAP-11 关键信息可达与表达**：必要——信息对实际任务关键。
  材料问：文字/音频/颜色/运动是否承担唯一关键信号，支持哪些设备与玩家路径；最小动作：按任务测适用视口、焦点与辨识，不可测的辅助技术写未测，不假称无障碍认证。
- **CAP-12 本轮交付与试玩条件**：必要——构建准备交给他人验证。
  材料问：测试者是否有可用构建、允许身份、清楚范围与安全档；最小动作：核对可进入与边界，工具打不开先查环境，未提供部署材料不直接判游戏 P0。

公共边界：长局保存必要，但不默认云端账号、多槽或离线收益；线性短体验明确终局即可，节奏重复中的掌握与自由表达可成立，不强加分支或经济策略。

## 五、最小可玩核验（按依赖限范围）

按序执行，逐依赖决定进入哪些相关深测：

1. 核当前任务与权限：入口、授权测试档、工具实际能力。
2. 本轮要评首访时，先由真正隔离的 R01 执行者取无提示记录并封存，再做有目标核验；材料结论、CAP 清单与正确路线不下发给 R01，工具预检或总控短探测不能称首访，同执行者读过答案不能再装独立，探测动过的旧档与新档隔离记录。
3. 用授权档从正常入口完成一个核心行动，确认真实状态与规则响应。
4. 走一个适用的取消、失败或中断。
5. 核一条模块连接或相关体验段；保存接续任务存在才查原档接续，不要求每个样机都有存档。
6. 逐依赖决定是否进入相关深测（R02–R05 适用项），写入第三节的验证范围决定。

- 已发生的玩法负面证据即使短路径也照记录，不因“只验完整性”延后或消失；短路径通过不等于策略、长期动机或整体品质已成立。
- 时长按预先选定的范围与预算，不把分钟数用尽当不合格线。

## 六、体验结构与采样登记

测试前按适用组合登记观察单元与替代采样；同一游戏可组合，未涵盖结构可增加并说明。

| 体验结构 | 观察单元 | 例外口径 |
|---|---|---|
| 循环型 | 行动—产出—新约束—下一圈 | 保留多圈与配置对比，按会话尺度采样 |
| 旅程型 | 线索/段落—理解变化—铺垫兑现—结束 | 不强制三圈、长期积累或分支选择 |
| 赛局型 | 开局—对抗/合作—结算—再参与 | 查局面与赛局边界，不以局外存档代替重连 |
| 掌握/表演型 | 输入—时序反馈—练习—表现 | 熟练重复可有价值，不以新决策频率判无聊 |
| 自由表达型 | 自定目标—创作—修改—成果 | 不要求外部任务链，查表达与调整是否成立 |

- 传统路径与替代实现按风险相称的同一标准：替代须正证据，传统按钮存在也不免同任务核查；不默认“替代要无限自证、传统即达标”，低风险非核心行不强制无限反证。
- 有价值困难与坏摩擦按可学线索、反馈、成本、回报与意图的正反证据判：作者说“故意”不免罪，没立即理解不判错；关键伤害仍按原尺与证据裁决。
- 实时连续片段：行动前记目标与预期，行动中连续控制取证，事后补结果，不逐帧停机；暂停、慢速或辅助输入须声明实际条件，未测的时序不猜。
- 各结构只写必要短句，不为所有类型新建附件。

## 七、完成标准与边界

- 范围内每个必要能力有材料依据、未知或合理省略理由；每个受限活动写明“仍可做什么”与最小下一步。
- 最小路径实际执行过才称“运行核验”；材料结论不可当运行时证据，深测缺口照常保留为未测。
- 完整报告仍为原十节：早期无实玩时第 1 节只写范围与限制、不裁好玩；第 2 节含材料与路由结论；第 5 节矩阵未核验照记；第 9 节推进任务沿 [开发交接](developer-handoff.md) 形成最小任务卡与复验条件。
- 本附件任何结果都不是游戏发布认证：能力齐全不等于好玩，四尺仍只裁已实证的体验损害。
