# game-design-review

游戏策划视角的黑盒试玩评审 skill：**设计哪里不成立、陌生玩家能否进入玩法、当前版本值不值得玩**，分别取证，不能用“没有 bug”替代。
保留四把尺子、阶段校准、保留/重做/观察标签、P0/P1/P2、红队和十节诊断报告；新增首访盲玩、真人校准、体验回归及非官方媒体评分。

当前整包版本：**0.3.0**。版本源见 [VERSION](VERSION)，变化见 [CHANGELOG](CHANGELOG.md)，固定版本与升级规则见 [VERSIONING](VERSIONING.md)。

## 一、目录与加载边界

```text
game-design-review/
├── SKILL.md                          # 唯一 skill 入口与四尺诊断；按任务加载附件
├── agents/
│   └── blind-player.md              # 隔离首访执行者的最小角色卡，不读主评审答案
├── references/
│   ├── orchestration.md             # 总控、轮次、隔离、状态交接、停止规则
│   ├── adjudication.md              # 候选→唯一问题台账→P0/P1/P2
│   ├── benchmarks.md                # 同约束游戏参照
│   ├── first-visit.md               # 自由首访、目标任务、最少辅助、理解链
│   ├── human-playtest.md            # 真人主持、记录、AI 分歧校准
│   ├── experience-regression.md     # 固定路径与全新盲玩两轨回归
│   └── critic-scoring.md            # AI 游戏评论员：IGN 方法启发，非官方
├── VERSION / VERSIONING.md / CHANGELOG.md
├── scripts/validate.py               # 静态校验与负向自测，不是浏览器执行器
├── tests/acceptance.md               # 协议验收场景，不冒充实际试玩
└── research/
    ├── RESEARCH.md                   # 历史设计取舍与后续进度
    └── ign-review-study.md          # 官方方法核查、四篇满分及两篇对照样本
```

附件不自动全部载入。主评审掌握基准，盲玩执行者只收角色卡与净化简报；媒体评分者在首访记录封存、深玩取证后进入，不反向污染首访。
`agents/` 是宿主调用时读取的角色卡，不是已自动注册的多代理服务；`research/` 只在查依据时读取，不混进每轮试玩上下文。

## 二、能力与产物

| 请求 | 加载文件 | 产物与边界 |
|---|---|---|
| 游戏验收、试玩评审、好不好玩、像不像游戏、策划/游戏感评审 | [SKILL.md](SKILL.md) + [参照库](references/benchmarks.md) 的相关部分 | 十节诊断；迭代/里程碑深度可选，红队可叠加 |
| 模拟新用户、首访盲玩 | [首访协议](references/first-visit.md) + 给子代理的 [角色卡](agents/blind-player.md) | 自主目标/选择/续圈证据；无提示与辅助严格分开 |
| 安排真人试玩、校准 AI | [真人协议](references/human-playtest.md) | 真实观察及分歧；没有参与者/记录只出计划 |
| 修改后体验回归 | [回归协议](references/experience-regression.md) | 固定路径与新盲玩分别验收、亮点保护、可追溯回归卡 |
| AI IGN、IGN 风格评分、给游戏打分 | [评分协议](references/critic-scoring.md) | 带证据的原创媒体评论、1–10 整数档；原型暂评/完整版本/不评分分开 |

请求“全部/完整/多角度”时：R01 首访 → R02 交互 → R03 策略 → R04 经济/回访 → R05 世界/文字 → R06 红队 → R07 综合；要求打分才加 R08。不存在的系统不强加，时间不足的系统未测。真人测试仅在有获授权参与者/证据时执行，不伪造也不承诺后台完成。
主 skill 不适用于纯 bug 测试或代码审查；评分不是诊断清单算术平均，总分不能掩盖核心 P0。

总控先读 [编排协议](references/orchestration.md)，综合读 [裁决协议](references/adjudication.md)。四尺是判据、轮次是视角；同版证据可复用，但不算重复复现。每轮短报告保留分歧，最终只维护一份 `findings.md`。

## 三、安装与执行条件

保留整个目录树，放入宿主配置的 `game-design-review/` skill 目录；本仓库维持原有 `name/description` 前置信息和 Markdown 格式。具体安装路径、触发语法、子代理隔离方式以当前宿主配置为准。
主入口仍叫 `game-design-review`，没有新增必须单独安装的 skill。可在支持的宿主中点名 `/game-design-review`，或直接用中文请求对应任务。
需要真实浏览器操作、截图与合适的测试账号/存档；动态判断还需要连续捕获能力。多代理隔离、计时与回访由宿主实际提供，本仓库不会自行创建浏览器服务或定时任务。
不能真正隔离上下文时，明确标“受限黑盒探索”；只有静态截图不判动态缺失。新浏览器也要核查服务端新档，回访则保留原档。

## 四、调用示例

一次完整调用：
> 使用 game-design-review，对本次提供入口与测试身份的 MUD 做完整多角度评审，最后附非官方 AI 媒体评分。冻结游戏版本，不边评边修；由总控依协议排轮次，最终交唯一 P0/P1/P2 台账、十节总报告、分轮证据和回归卡。

用户不必点名各附件。没有隔离能力不能声称独立新手，没有浏览器能力不冒充实际试玩。


首次访问：
> 用 game-design-review 对这个游戏入口做独立首访盲玩。先无提示探索，再做最少辅助对照；不要把策划、正确路线或旧报告交给首访执行者。给出十节短报告和有证据的体验回归卡。

当前 MUD 原型评分：
> 用 game-design-review 的非官方 AI IGN 模式评这个版本。入口、测试账号与权限见本次简报。先盲玩，再验证核心循环、等待和原档回访；给“原型当前体验（暂评）”整数分、评论和相邻分档理由。没有足够证据就不打分，不给未来像素表现加分。

修改后复验：
> 对照这些体验回归卡复验新版。先做固定路径，再用未见答案的执行者盲玩；两轨分别判定，不因脚本跑通而关闭新手问题。

真人校准：
> 根据这批获授权的匿名真人试玩记录，对照同版 AI 记录分析分歧；没有记录的情绪、访谈和留存不要补写。给下一轮验证计划。

以上文字是任务模板，不代表本仓库已有可运行的游戏 URL、测试账号或实际分数；执行时补齐对应项目的真实简报。

## 五、非官方 AI IGN 是什么

名称：**AI 游戏评论员｜IGN 方法启发，非官方**。它是供有浏览器能力的代理执行的评分协议，不是 IGN 官方服务、授权评分、训练好的 IGN 分数预测模型或真人用户研究替代品。
参考资料与读取范围见 [IGN 研究记录](research/ign-review-study.md)：官方量表、Baldur's Gate 3 / Tears of the Kingdom / Disco Elysium: The Final Cut / Celeste 的 10 分样本，以及 Hades 9 分、Starfield 7 分对照。
评分评当前可玩体验，不给开发潜力加分；原型暂评必须保留阶段和范围标签，不能与完整作品评分直接混比。版本、实际时长、证据及未测范围必须与数值一起展示。
只有代码、策划或这份 skill 仓库时，输出所需证据与待测计划，不编游戏分数。对已观察到的产品问题仍应明确下负面结论，不能以“资料有限”抹掉已确认损害。

## 六、资料与安全

方法与来源见 [参照库](references/benchmarks.md)、[历史研究](research/RESEARCH.md) 和 [IGN 研究](research/ign-review-study.md)。新增时间预算、反证门槛和提示流程是本仓库的工程化约定，未经真人统计验证。
真实游戏报告和回归卡默认留在被评项目，获授权后才归档；此仓库保存协议，不默认公开玩家资料。认证状态、cookies、令牌、联系人和未脱敏录制不得提交。

## 七、报告包与版本复现

获授权后在被评项目保存 `docs/reviews/<game-build>/<run-id>/`：`run.md`、`rounds/`、`evidence/`、`findings.md`、`report.md`、`regression.md`，评分时加 `critic.md`。
`run.md` 记录 skill_version、skill_commit、game_build、report_schema、critic_scale、权限、能力与实际覆盖；原型暂评和完整版本分开。未授权归档时使用同名会话分节，不编造文件链接。
每轮报告只描述该视角；总报告保留十节并引用唯一最终问题 ID，避免多个清单互相矛盾。严重度、置信度、转段和修复次序分开，不投票平均、不机械取最严意见。

## 八、自检与当前边界

使用 Python 3.9 或更高版本，仅依赖标准库。

```sh
python scripts/validate.py --self-test
```
校验版本、链接、主文件 420 行上限、触发范围、Phase 和十节结构；负向自测确保失配被发现。它不是完整 YAML/Agent Skills 规范验证器，更不是已实现的浏览器或自动多代理服务。
[协议验收场景](tests/acceptance.md)用于合成输入推演，正式端到端验证需实际宿主、可玩入口和可丢弃存档。当前发行不声称完成目标 MUD 试玩、真实心流测量或真人校准。
安装须同步整包；缺 tag 时按合并 commit 固定，不能把 VERSION 文件误称远端标签已发布。版本号并不保证同一模型必然给出完全相同的评价，仍需保留原始证据。
