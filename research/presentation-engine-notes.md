# 表现形态、MUD 界面与工具路线研究

核查日期：2026-09-20。服务于 [R09](../references/presentation-transition.md)，仅在需要参照或技术建议时读取，不向首访执行者下发。
这是官方页面/开发者说明的研究摘要，不是本次亲手试玩或构建测评。下文“迁移问题”均是本项目推导；历史布局、官方功能声明不能代替当前版本实测。

## 一、四种表现参照，借鉴机制而非照抄皮肤

| 参照及一手出处 | 本次资料支持的内容 | 借鉴问题与边界 |
|---|---|---|
| [Nexus 客户端布局](https://nexus.ironrealms.com/The_Game_Client)；[Evennia 网页客户端](https://www.evennia.com/docs/latest/Components/Webclient.html) | Nexus 文档列主输出、输入、快捷动作、状态、地图及通信；Evennia 文档列窗口布局、信息路由、历史与字体等插件 | 如何分开当前状态、行动和历史？双入口是否一致？Nexus 为历史界面说明，不把所有面板及可拖动布局当原型必需品 |
| [A Dark Room 开发者介绍](https://press.doublespeakgames.com/adr/index.html) | 从点火动作起步，随信息及交互层次展开改变策略 | 新功能是否在有意义的时刻出现？渐进揭示不等于隐藏当前必要规则；未实际录制不声称某种渐变存在 |
| [Fallen London 官方介绍](https://www.failbettergames.com/games/fallen-london) | 官方定位文字冒险/角色扮演，桌面及移动浏览器布局、短时故事游玩 | 文字、插画及行动信息如何分工？可作为文字长期成立的参照，不据宣传证明实际留存，不照搬商业化/行动点系统 |
| [Cogmind 开发者：界面放大](https://www.gridsagegames.com/blog/2024/01/full-ui-upscaling-part-1-history-and-theory/) | 2024-01-02 的开发记录讨论地图、文本放大与布局约束 | 符号/终端地图能否验证空间？风格不得掩盖阅读问题；它是界面参照，不是传统多人 MUD，不认定文章反映所有现行版本 |

使用风格卡只写：`来源/日期与读取范围｜想借鉴的信息关系｜对应任务｜预计收益｜潜在损失｜实际验证或待测`。
文字、终端、故事卡、符号地图、像素均可成为成品；不把精细美术当质量分，也不把极简自动赞成有风格。实际布局由目标设备和任务决定，不套固定五栏模板。

## 二、阅读与可访问性的依据

[W3C：暂停、停止、隐藏](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)讨论适用条件下自动运动/更新内容的用户控制。R09 据此检查日志回读、自动滚动及新消息提示，但不等于已经完成 WCAG 合规审计，也不强迫暂停在线世界。
[MDN：Canvas](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/canvas)说明画布内容与语义 HTML 的可访问性差异。迁移画布时应重新设计输入、辅助技术及证据采集；没有 DOM 控件不是游戏缺陷的充分证据。
本项目建议把中文正文、当前情境、操作条件和历史分别组织，支持目标视口下阅读与输入；字号、行距及信息密度须实测，不给“所有中文游戏必须用某字号”的固定标准。

## 三、工具按职责比较，不给统一排名

下表仅是本次官方资料所支持的职责线索，不代表已经验证其适合被评项目。作具体建议时重查目标版本；实际预算、已有资产、团队和发布要求未知就保留条件。

| 职责与候选 | 官方依据 | 需要项目验证什么 |
|---|---|---|
| 多人世界服务端：Evennia | [框架介绍](https://www.evennia.com/docs/latest/Evennia-Introduction.html)描述 Python MU* 基础、对象/角色/房间等；网页客户端可定制 | 是否真正需要多人持久世界？现有服务是否已够用？自定义经济与图形协议仍需开发，不是换前端就自动完成同步 |
| 叙事编写：ink | [官方介绍](https://www.inklestudios.com/ink/)将其定位为可嵌入游戏引擎的叙事语言 | 是否只是缺事件/对话工具？不要拿叙事语言替代经济系统和多人服务端 |
| Web 2D 框架：Phaser | [官方入门](https://docs.phaser.io/phaser/getting-started/what-is-phaser)说明面向浏览器的 2D 游戏框架 | 原 Web 规则/UI 可保留多少？需要哪些场景、输入和游戏框架能力？不能因为支持 Web 就声称已有项目迁移轻松 |
| 2D 渲染库：PixiJS | [官方介绍](https://pixijs.com/8.x/guides/getting-started/intro)说明渲染、场景等能力 | 是只缺地图渲染，还是缺完整制作工具？账号、存档、规则等不能假定已被渲染库解决 |
| 完整引擎：Godot | [功能介绍](https://godotengine.org/features/)及[Web 导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html) | 截至核查，稳定文档注明 Godot 4 C# 的 Web 导出限制、WebGL 2/Compatibility 和网络约束；选语言和发布平台时必须重新核实，并验证目标构建，不能只凭名字推荐 |
| 代理工作流候选：Defold | [官方代理开发说明](https://defold.com/manuals/ai-agents/)的检索可读片段说明模型无关的编辑器/运行时自动化接口；本次全文直读失败 | 接口声明只构成试制理由；权限、调用、构建、输入和截图必须在真实环境验证，不据此声称比其他引擎更易被 AI 开发 |
| 桌面外壳：Electron | [官方介绍](https://www.electronjs.org/docs/latest)说明用 JavaScript/HTML/CSS 构建桌面应用 | 已有 Web 前端是否可保留？需另测分发、更新、离线、输入、存档；生成窗口不等于完整客户端体验 |

Unity、GameMaker、其他 MUD 框架或桌面外壳在有明确约束时可以加入候选；本次未重新核查它们的版本/许可，不沿用先前对话中的价格或平台细节。
引擎许可、价格、维护状态、浏览器限制及插件兼容会变化；实际建议必须注明官方来源、核验日期、尚未完成的项目级验证。

## 四、沉淀成决策的方法

1. 先定位三条轴和当前体验损害，再讨论美术与工具；技术方案至少包含“保留当前栈”的基线。
2. 先补能公平验证玩法的最低 UX，不要求文字端豪华装修；空间/动作假设超出文字能力时，提出最小可操作切片。
3. A/B 先锁规则、内容、状态和预算；两种形态同时改玩法时只能比较整个方案，不能归因于图形。没有 B 就只有验证计划。
4. 迁移清单区分数据/规则规格/动作结果契约与语言绑定代码、资产、工具；从文档只能提出假设，不能凭浏览器猜耦合或承诺无损复用。
5. 现有体验缺陷进 R07 的 P0/P1/P2；未来路线、未测能力和试制任务不当产品违规，不因选引擎改变媒体评分。

本次未发布风格资产、未复制他人素材、未给当前游戏做技术选型裁决，也未完成游戏/引擎的比较试玩。可执行流程、证据门槛与退出条件以 R09 为准。
