# 条件化能力契约与通用判据（提案）

与 [流程](01-workflow.md) 配套。0.6.0 的 [能力对照](../../../references/capability-review.md) 已有未宣称必要能力、替代与差距分流，本文件建议把它们变成前置审查可直接使用的工作表，不声称现行协议完全没有这些规则。

## 1. 为什么仍需要具体清单

目标使用者可能不知道要要求存档、引导、恢复或输入边界。让审查员只问“作者想验证什么”不足以发现未知遗漏；但让所有项目照做商业功能大全也会制造无谓工作。

采用两层结构：上层按玩家任务判断能力是否必要，下层用具体功能/路径查漏。具体清单不能删除，常规按钮也不能直接等于能力。对当前不需要的能力给一次有理由的省略；不必列举所有平台上所有无关功能。

## 2. 每项能力契约的最小字段

```text
契约编号 / 玩家任务 / 当前验证目标：
必要性来源：玩法依赖、投入成本、目标玩家、平台约束、项目承诺、匹配参照
阶段要求：本阶段必要 / 下一目标前必要 / 增强候选 / 合理省略
材料状态：明确设计 / 设计部分明确 / 设计未交代 / 不适用
玩家端状态：具备 / 部分具备 / 已确认缺失 / 未核验（保留现行四态）
实际实现 / 等价替代 / 当前可验证边界：
查找和执行路径 / 正常与边界证据 / 不确定性：
最小补齐候选 / 暂不要求的内容 / 复验条件：
关联 C 行、D/B/L/G、推进决定与任务：
```

“材料未交代”不映射成“玩家端已确认缺失”。“合理省略”需要能力对当前目标不必要或已有有效替代的依据；“未实现”“作者没说”“实现很贵”本身都不够。证据支持局部缺失时明确范围，不能为了证明全局没有而无限搜索。

阶段要求可有暂定状态与置信理由。若作者把本来面向陌生玩家的试玩临时改成“只供本人演示”以回避问题，应记录目标变化，并保留原目标下的缺口；不能回写原判定。

## 3. 候选契约 CAP-01–CAP-12

这些是拟议测试契约编号，不是新增 D/B 问题编号。完整评审检查适用项；局部迭代检查变更及依赖。材料审查用同一能力生成问题，运行时测试只执行真实存在或可安全验证的路径。

| 编号 / 能力 | 何时必要 | S1 设计问题 | S2 最小核验 / 允许替代 |
|---|---|---|---|
| CAP-01 进入与开始 | 要交给目标玩家独立使用 | 真实入口、开始/继续条件、受支持环境是否明确？是否依赖作者后台操作？ | 从正常入口到可行动状态；无账号游戏不强求注册，无主菜单也可直接进入 |
| CAP-02 首访、学习与求助 | 新规则/输入需陌生人理解 | 玩家如何发现第一步、理解结果、在受阻时获取线索？ | 无提示路径与迁移任务；场景示范、渐进提示可替代教程关，不因无教程按钮判缺 |
| CAP-03 动作受理、结果与状态 | 行动结果影响后续行为 | 成功、拒绝、处理中、结束如何区分？隐藏信息服务什么？ | 操作与前后状态可对应；文字、声音、视觉均可承担；没有音频能力不能否定声音 |
| CAP-04 核心规则与主打价值 | 所有受评核心，但按体验结构变化 | 承诺的策略、发现、表达或叙事后果由什么规则产生？ | 验证一段主打体验；不同选项不强制数值收益不同，线性体验不强求分支 |
| CAP-05 模块连接 | 任务跨多个系统 | 输入输出、资源流、对象状态与解锁条件是否接上？ | 完成一条跨模块路径；能买但不能使用、能放建筑但不参与规则应有证据，不凭图标推断 |
| CAP-06 推进、成长或终局 | 体验需要阶段变化、再参与或结束 | 第一段之后发生什么？成长如何使用？短作品如何明确结束？ | 至少到相关节点；收藏、叙事、表演、明确终局可替代数值成长，不要求无限续圈 |
| CAP-07 中断、成果保护与接续 | 投入超出一次完整短局，或跨会话积累 | 保存对象、触发/失败、恢复边界、可能损失是否定义？ | 授权档正常离开再返回核对关键状态；自动保存/检查点/持久世界可替代手动存档；短局可省持久保存 |
| CAP-08 失败、重试与恢复 | 有失败、阻断或不可完成状态 | 原因、代价、退出与重试规则是否清楚？ | 在废档执行适用失败与后续路径；永久死亡可成立，不强制撤销或无限复活 |
| CAP-09 成本、取消与不可逆行动 | 有消费、建造、选择或删除等代价 | 是否知道作用对象与后果？确认和撤销如何匹配风险？ | 正常提交、取消或拒绝路径；低风险不强制层层确认，知情高风险不强制全额退款 |
| CAP-10 输入、空间与导航 | 存在对应输入或空间任务 | 能否看清、选中、定位、移动并恢复控制？ | 支持设备上完成代表任务；固定视角、地图层可替代旋转俯仰，2D 不借 3D 功能数量判差 |
| CAP-11 信息可达与表达 | 信息对实际任务关键 | 文字/音频/颜色/运动是否承担唯一关键信号？支持的设备和玩家路径是什么？ | 适用视口、焦点、辨识、字幕/控制等按任务测试；不可测辅助技术写未测，不假称完成无障碍认证 |
| CAP-12 本轮交付与试玩条件 | 构建准备交给他人验证 | 测试者是否有可用构建、允许身份、清楚范围和安全档？ | 核对可进入与边界；工具打不开先查环境，未提供产品外的部署材料不直接判游戏 P0 |

这些条目不是功能数量得分表。必要能力缺失应明确记录与处理，全部有入口也不保证设计成立。

## 4. 设计合理性：比“有没有”多查一层

对适用核心依次问：目标是否可到达；前置条件是否循环依赖；产出是否能进入后续行为；资源不足是否存在设计允许的出口；失败是否结束得明确；多个模块对同一对象的规则是否一致；主打体验是否被另一机制架空。

材料明示“建 A 要 B、获得 B 只能先建 A、无初始资源和替代路径”时，可确认这份规格的启动矛盾。若仅没找到初始资源描述，则仍可能是材料遗漏，不能把未知补成死锁。落到实际构建后再排除初始库存、替代获得方式、阶段限制等。

“没有改变数值”不等于选择虚假；“有十种资源”不等于策略深；“有宏大世界观”不等于叙事兑现；“各页能点开”不等于模块连接。每条推演都应对应最小实际验证，而不是成为审查员自己的新策划书。

## 5. 最小方案与有意省略的边界

以长期经营的接续为例：优先验证能恢复当前任务必需的资源、设施状态、进度及待处理事项；先提出最小可靠接续，不默认多槽、云端、跨设备和账号体系。是否需要数据版本兼容、恢复旧档或离线结算取决于接下来的更新与玩家任务，不在所有样机强制加入。

但是“最小”不能只存一个资源数字、丢掉任务必需的队列或解锁；不能把刷新后重新开局叫接续；不能为了证明演示成功静默修档。

对无持久保存的短局，仍检查结束/重新开始的边界是否合理。对有意不可回滚的玩法，检查知情损失与退出规则，而不是以“设计如此”免除所有成果保护。

## 6. 跨品类：体验结构先于经济循环模板

| 结构 | 优先观察单位 | 对默认判据的替换 |
|---|---|---|
| 循环型 | 行动—产出—新约束—下一圈 | 保留多圈、成长与配置对比；按会话尺度采样 |
| 旅程型 | 线索/段落—理解变化—铺垫兑现—结束 | 不强制可重复三圈、长期积累或分支选择 |
| 赛局型 | 开局—对抗/合作—结算—再参与 | 检查局面、对手/队友条件与赛局边界，不以局外存档代替重连 |
| 掌握/表演型 | 输入—时序反馈—练习—表现 | 熟练重复可有价值；不能只以新决策频率判无聊 |
| 自由表达型 | 自定目标—创作—修改—成果 | 不要求外部任务链；检查表达与调整是否成立 |

同一游戏可组合，未涵盖类型允许增加结构并说明。玩家正在学什么、熟悉后还剩什么仍是好问题，但不能成为唯一乐趣来源。探索、叙事、表达、休闲等回报必须有实际依据，不能靠标签自动通过。

五分钟、三十分钟、三圈、两路线均是采样方案而非跨品类质量定律。例外应在测试前登记；新发现迫使调整时留修订理由与旧证据，不能为了消除负面结果改尺子。只测短片段不得外推后期。

## 7. 有价值的困难与坏摩擦

区分操作性阻力（界面妨碍已知行动）、玩法性阻力（需要学习、练习、推理或承担风险）、表达性阻力（不确定、压迫或失控服务作品意图）。它们可能混合，需要分别指出。

游戏不必立即公布所有信息，也不必让每个决定都可撤销。判缺陷应说明实际损害、可学习/应对线索、风险与回报是否相称、最强替代解释。作者说“故意”不证明成立；审查员没马上理解也不证明设计失败。关键伤害仍按原尺与证据裁决，不因这些区分削弱查漏职责。

## 8. 同类对照：早期查漏，后期评深度

S1 使用轻量候选基准推导必要能力，已知任务可先检；不等待完成全量市场研究。S3 对需要解释的差距核查匹配作品的具体行为、版本、平台和来源。官方声明只证明对应功能/意图，不证明手感或品质；不把几款作品推成行业普遍规则。

传统与替代实现采用相同风险相称的证据标准：完成同一任务、成本和恢复、相关不同局面、关键不利条件。不是传统路径只需“按钮存在”，创新路径却需要证明全球最优；低风险非核心行也不强制无限反证。

核心能力与表现规格分开：借鉴保存、引导、决策反馈的目的，不复制商业内容规模。未找到已证实差距可如实写，无差距配额，无 P0 配额，无“像大作才成熟”的标准。

## 9. 矩阵与严重度的拟议改进

现行实现四态可保留；现行对照五值混合满足程度、实现关系和可判定性，建议在未来版本拆为：`任务满足程度 / 实现方式与替代 / 相对参照取舍 / 证据状态与边界`。一个替代可同时更易上手而规模效率更差，不强塞进单一“替代成立”。

这属于报告契约变更，须同步 schema、示例、校验器及迁移说明，不在本 PR 默默改字段。必要性、能力状态、差距、真实损害、阶段推进和修复顺序彼此独立；不把矩阵行数转分数。

P0/P1/P2 继续描述体验损害，不以“改设计/改代码/改美术”预先决定原因。技术故障单列 B；原因不明保留待确认与已知行为，不用降严重度掩盖置信不足。门槛视图可引用 D、B 或关键未知，不因为 B 没有设计 P 级就忽略其对本轮验收的影响。

## 10. 执行能力与后续专项优先级

优先补实时动作取证、叙事/解谜、赛局/协作、可达性等会改变核心测法的模块，再按真实需求扩张类型。3D 镜头模块不能自动覆盖格斗、竞速或音游的全部体验；经营仍可保持当前较细的专项。

实时场景应按连续片段操作与捕获、事后标注，避免逐动作写日志占用行动窗口；暂停、慢速或辅助输入要记录条件。随机/多人样本控制局面与对手条件，重复采样或保留不确定性，不以两次结果相同证明策略无效。

可用获授权、来源清楚的中后期档检查晚期状态；这不等于验证从开局成长到该状态的过程。长期等待只能用真实间隔或真实历史证据，不调时钟、清档或承诺后台任务冒充。以上均是执行协议建议，需实际宿主验证。
